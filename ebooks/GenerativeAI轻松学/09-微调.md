# 09-微调

## 开篇除恐

前面我们用RAG让AI"查资料"回答问题，效果不错。但你可能发现：AI的回答风格还是太"通用"了。

比如你的电商客服，即使查了知识库，回答还是有点**机械**，不够像你们品牌的语气。

怎么办？**给通用模型"开小灶"**。

这一章讲的**微调（Fine-tuning）**，就是让AI从"通才"变成"专才"的技术。

**微调不是重造模型，是给现成的模型做专业培训。**

---

## 白话化：把术语扒光了看

### 模型适应（Model Adaptation）

**大白话**：模型适应就是**让通用模型学会特定领域的知识或风格**。

**原书说明**：模型适应包括多种技术，从轻量级的prompt tuning到重量级的全参数微调。

### 微调（Fine-tuning）

**大白话**：微调就是**在预训练好的模型基础上，用你自己的数据再训练一轮**。

就像你请了一个哈佛毕业生（预训练模型），但他不懂你的业务。你给他培训3个月（微调），他现在既聪明又懂你的业务。

**原书说明**：Fine-tuning是在基础模型上，使用特定任务的标注数据进行额外训练。

### 预训练（Pre-training）

**大白话**：预训练就是**让AI读遍互联网**，获得通用知识。

**原书说明**：Pre-training使用大规模无标注文本，训练模型学习语言规律。

### 监督微调（SFT）

**大白话**：SFT就是**给AI看标准答案**。

你准备一堆"问题-答案"对，让AI照着学。比如：
- 问："怎么退货？" 答："15天无理由，保留包装..."
- 问："发什么快递？" 答："顺丰和圆通..."

**原书说明**：SFT使用高质量的prompt-response对，训练模型学习特定任务。

### RLHF（Reinforcement Learning from Human Feedback）

**大白话**：RLHF就是**人类打分，AI进步**。

AI生成多个回答，人类评价哪个更好。AI学习人类的偏好，以后生成更符合人类喜好的回答。

**原书说明**：RLHF结合强化学习和人类反馈，Align模型输出与人类价值观。

### LoRA（Low-Rank Adaptation）

**大白话**：LoRA就是**只改模型的一小部分，不动整体**。

传统微调要改模型所有参数，成本极高。LoRA只插入两个小矩阵，只训练这两个小矩阵，其他参数冻结。

**好处**：速度快、成本低、效果接近全参数微调。

**原书说明**：LoRA通过低秩矩阵分解，大幅减少可训练参数数量。

### QLoRA

**大白话**：QLoRA就是**把LoRA再压缩**，用更少的内存跑。

在LoRA基础上，用4-bit量化存储模型，进一步减少显存需求。

**原书说明**：QLoRA是LoRA的量化版本，可在单张消费级GPU上微调大模型。

## 直觉先行：用"专业培训"理解微调

想象你要培训一个**客服专员**：

**阶段1：通用培训（预训练）**
- 大学读了4年，学了语文、数学、逻辑...
- 能说会道，但不懂电商

**阶段2：岗前培训（SFT）**
- 你给他看1000个"客户问题-标准答案"
- 他学会了你们公司的回复风格

**阶段3：实习+ feedback （RLHF）**
- 他回答客户问题，你给他打分
- 好的回答多给奖励，不好的给惩罚
- 他慢慢学会怎么回答更得体

**阶段4：专项技能（LoRA）**
- 不用重新培养一个客服
- 只给他一本《VIP客户应对手册》
- 他看完就能应对VIP客户

**微调就是阶段2-4，基于已经培养好的通才（预训练模型）做专项提升。**

## 例子贴身

### ☼ 热身：用OpenAI API做简单微调

**原书** 展示了Azure OpenAI和OpenAI的微调流程，包括准备数据、上传文件、启动微调任务、部署微调模型。

**自编** 简化版，用OpenAI的微调API：

```python
from openai import OpenAI

client = OpenAI(api_key="YOUR_API_KEY")

# 1. 准备训练数据（JSONL格式）
# 每行是一个对话，包含system、user、assistant
training_data = [
    {
        "messages": [
            {"role": "system", "content": "你是XX电商的客服代表小X，语气友好专业。"},
            {"role": "user", "content": "怎么退货？"},
            {"role": "assistant", "content": "您好！我们支持15天无理由退货，请保持商品及包装完好，联系客服获取退货地址哦~"}
        ]
    },
    # ... 更多样本（至少需要50-100条）
]

# 2. 上传训练文件
with open("training_data.jsonl", "w") as f:
    for item in training_data:
        f.write(json.dumps(item) + "\n")

file = client.files.create(
    file=open("training_data.jsonl", "rb"),
    purpose="fine-tune"
)

# 3. 启动微调任务
job = client.fine_tuning.jobs.create(
    training_file=file.id,
    model="gpt-3.5-turbo",  # 基于哪个基础模型
    suffix="customer-service-v1"  # 微调模型名称后缀
)

print(f"微调任务已启动: {job.id}")

# 4. 等待完成（通常几小时到1天）
# 5. 使用微调后的模型
response = client.chat.completions.create(
    model="ft:gpt-3.5-turbo:your-org:customer-service-v1",
    messages=[
        {"role": "user", "content": "怎么退货？"}
    ]
)
```

**成本**：OpenAI微调gpt-3.5-turbo约$0.80/1K tokens训练，推理时比普通模型贵一点。

### ☼☼ 正经：给客服机器人做风格微调（贯穿例子·第9章）

**场景**：你的客服机器人用RAG后回答准确了，但风格还是太"通用"。老板想要**有品牌性格**的客服。

**原书** 展示了LoRA的原理、QLoRA的量化技术、RLHF的流程。

**自编** 你决定用微调让客服机器人有"性格"：

**方案对比**：

| 方案 | 成本 | 效果 | 适用场景 |
|------|------|------|----------|
| Prompt Engineering | 低 | 一般 | 快速调整 |
| RAG | 中 | 准确但风格通用 | 知识库问答 |
| Full Fine-tuning | 极高 | 最好 | 大公司、专用场景 |
| LoRA/QLoRA | 中低 | 接近Full FT | **推荐** |

**实施步骤**：

1. **准备数据**：收集历史客服对话，筛选高质量对话
2. **构建训练集**：至少100组"问题-理想回答"对
3. **选择基座模型**：gpt-3.5-turbo 或 llama-2-7b（开源）
4. **微调**：用LoRA方法，在单张A10 GPU上训练
5. **评估**：对比微调前后的回答风格

**训练数据示例**：

```json
{
  "messages": [
    {"role": "user", "content": "你们发什么快递？"},
    {"role": "assistant", "content": "亲，我们默认发顺丰快递，速度超快的！📦 如果偏远地区会转圆通哦~"}
  ]
}
```

**微调后的效果**：

| 指标 | 微调前 | 微调后 |
|------|--------|--------|
| 品牌语气一致性 | 45% | 89% |
| 用户满意度 | 4.2/5 | 4.7/5 |
| emoji使用恰当性 | 12% | 85% |

**原书** 还提到了微调的挑战：
- 需要高质量训练数据
- 成本较高（Full FT），LoRA降低成本
- 可能 overfit 到训练数据
- 需要持续监控和更新

## 这一章要带走的东西

- 微调不是重造模型，是在预训练模型基础上做专业培训。
- 预训练 = 通才教育，微调 = 专业培训。
- SFT = 给AI看标准答案，监督学习。
- RLHF = 人类打分，AI学习人类偏好。
- LoRA = 只训练小矩阵，低成本高效微调。
- QLoRA = 量化版LoRA，单卡可跑。
- Prompt tuning和adapter modules是更轻量的替代方案。
- 微调适合需要**特定风格、特定领域知识**的场景。
- 我们的客服机器人经过微调，有了品牌性格。

**就这样。**
