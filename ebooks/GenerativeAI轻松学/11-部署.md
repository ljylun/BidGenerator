## 白话化：把术语扒光了看

### LLMOps / MLOps

**大白话**：Ops就是**运维**。LLMOps专门管AI模型的生命周期，MLOps管所有机器学习模型。

**原书说明**：LLMOps是MLOps在LLM场景下的 specialization ，包括prompt管理、模型监控、版本控制等。

### 延迟（Latency）

**大白话**：延迟就是**用户发出请求到收到回复的时间**。

理想情况：<1秒
可接受：1-3秒
差强人意：3-5秒
 unacceptable ：>5秒（用户会以为卡了）

**原书说明**：Latency是生产环境的核心指标，包括TTFT（Time To First Token）和TPOT（Time Per Output Token）。

### 吞吐量（Throughput）

**大白话**：吞吐量就是**系统每秒能处理多少个请求**。

比如你的客服机器人每秒能同时回答100个用户问题，吞吐量就是100 QPS（Queries Per Second）。

**原书说明**：Throughput衡量系统的处理能力，需要根据预期用户量规划。

### 缓存（Caching）

**大白话**：缓存就是**把常见问题的答案存起来，不用每次都问AI**。

比如"怎么退货？"这个问题一天被问1000次，第一次问AI，后面999次直接从缓存取答案。

**效果**：响应速度从1秒降到0.1秒，成本降90%。

**原书说明**：LLM缓存存储prompt-response对，显著降低延迟和成本。

### 限流（Rate Limiting）

**大白话**：限流就是**防止有人恶意刷接口**。

比如每个用户每分钟最多问20个问题，防止有人恶意消耗资源。

**原书说明**：Rate limiting保护API不被滥用，确保公平使用。

### 水平扩展（Scaling）

**大白话**：水平扩展就是**人多的时候多开几个窗口**。

高峰期1000并发，平时100并发。你准备10台服务器，平时开2台，高峰期开10台。

**原书说明**：Horizontal scaling通过增加实例数量应对流量增长。

### 容器化（Containerization）

**大白话**：容器化就是**把应用和它的 dependencies 打包成一个"集装箱"**。

你在开发环境能跑，打包成Docker镜像，放到任何服务器都能跑，不会出现"在我机器上能跑"的问题。

**原书说明**：Docker容器确保环境一致性，简化部署和扩展。

### PTU / PAYGO

**大白话**：
- PTU（Provisioned Throughput）：**包月套餐**，预买一定吞吐量，适合稳定流量。
- PAYGO（Pay-As-You-Go）：**按量付费**，用多少付多少，适合波动流量。

**原书说明**：Azure OpenAI提供PTU和PAYGO两种部署选项。

## 直觉先行：用"开餐厅"理解部署

想象你开了一家**AI餐厅**：

**实验室阶段**：
- 你在家做饭，给10个朋友吃
- 味道好，但一次只能招待10人
- 朋友说："能不能开个店？"

** deployment 阶段**：
1. **租店面**（买服务器/云资源）
2. **装修**（配置环境、装Docker）
3. **招员工**（部署多个实例）
4. **排队系统**（限流、队列）
5. **收银系统**（计费、监控）
6. **卫生检查**（安全、合规）
7. **高峰期加人手**（自动扩展）
8. **老顾客免排队**（缓存VIP回答）

**核心思想**：从"能做"到"能做且稳定、快速、便宜、安全"。

## 例子贴身

### ☼ 热身：用Docker打包AI应用

**自编** 把你的客服机器人打包成Docker镜像：

```dockerfile
# Dockerfile
FROM python:3.11-slim

WORKDIR /app

# 安装依赖
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 复制代码
COPY . .

# 环境变量
ENV OPENAI_API_KEY=${OPENAI_API_KEY}
ENV REDIS_URL=${REDIS_URL}

# 启动服务
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

```bash
# 构建镜像
docker build -t customer-service-bot:latest .

# 运行容器
docker run -d -p 8000:8000 \
  -e OPENAI_API_KEY=sk-... \
  -e REDIS_URL=redis://localhost:6379 \
  customer-service-bot:latest
```

**效果**：无论在开发机、测试环境、生产环境，行为完全一致。

**关键指标**：

| 指标 | 目标 | 实际 |
|------|------|------|
| 平均延迟 | <2s | 1.8s |
| P95延迟 | <5s | 4.2s |
| 吞吐量 | 1000 QPS | 1200 QPS |
| 可用性 | 99.9% | 99.95% |
| 成本 | $500/天 | $420/天 |

**优化手段**：

1. **缓存热点问题**：
```python
# 缓存命中率60%，成本降60%
@lru_cache(maxsize=1000)
def get_cached_answer(question_hash):
    return answer_question(question_hash)
```

2. **模型路由**：
```python
# 简单问题用小模型，复杂问题用大模型
def route_question(question):
    if is_simple_question(question):
        return "gpt-3.5-turbo"  # 快、便宜
    else:
        return "gpt-4-turbo"    # 聪明、贵
```

3. **自动扩展**：
```yaml
# Kubernetes HPA
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: customer-service-bot
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: customer-service-bot
  minReplicas: 3
  maxReplicas: 20
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
```

4. **监控告警**：
- 延迟超过3秒 → 告警
- 错误率超过1% → 告警
- GPU利用率超过90% → 自动扩容

**原书** 还提到了：
- 安全与合规：加密、访问控制、数据驻留
- 成本管理：PTU vs PAYGO选择
- 回滚策略：新版本出问题快速回退
