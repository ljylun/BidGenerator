## 二、术语小词典

全书出现过的术语，一句话讲清：

| 术语 | 一句话解释 |
|------|-----------|
| **Transformer** | 一个"读懂 + 吐出"的流水线架构模板 |
| **Encoder** | 负责读入、理解输入的模块 |
| **Decoder** | 基于理解结果，逐词生成输出的模块 |
| **Self-Attention** | 让每个词根据上下文动态调整身份的机制 |
| **Token** | 文本被切分后的最小单元，可以是词、子词或字符 |
| **Embedding** | 把词/Token 映射成向量的过程，相当于"给词一个数字身份证" |
| **Positional Embedding** | 给词加位置标签，让模型知道顺序 |
| **Layer Normalization** | 神经网络里的稳定器，防止数值飘走 |
| **Skip Connection** | 把输入直接绕道传到输出，防止信息丢失 |
| **BERT** | 只用 Encoder 的 Transformer 变体，适合理解任务 |
| **GPT** | 只用 Decoder 的 Transformer 变体，适合生成任务 |
| **T5** | Encoder-Decoder 结构的 Transformer 变体，适合转换任务 |
| **Retriever** | QA Pipeline 里的检索器，负责缩小答案范围 |
| **Reader** | QA Pipeline 里的阅读器，负责从段落里抠答案 |
| **Pipeline** | 把多个步骤串成流水线，问题依次流过每个节点 |
| **Extractive QA** | 抽取式问答：从原文里抠答案，不自己编 |
| **Scaling Law** | 模型性能随规模/数据/算力增长的规律，有收益也有代价 |
| **Sparse Attention** | 稀疏注意力：只关注真正相关的词，提高效率 |
| **Multimodal** | 多模态：模型同时处理文本、图像、声音等多种输入 |
| **Fine-tuning** | 在预训练模型基础上，用特定领域数据再做一次训练 |
| **Haystack** | 一个帮你快速搭建 QA Pipeline 的框架 |

## 三、一页纸速查

### Transformer 速查卡

```
输入文本
  ↓
分词 (Tokenization)
  ↓
词嵌入 (Token Embedding) + 位置嵌入 (Positional Embedding)
  ↓
┌─────────────────────────────────────────┐
│           Encoder（读懂）                │
│  ┌─────────────────────────────────┐    │
│  │  Multi-Head Self-Attention     │    │
│  └─────────────────────────────────┘    │
│  ┌─────────────────────────────────┐    │
│  │  Feed-Forward Network          │    │
│  └─────────────────────────────────┘    │
│  （多层堆叠，每层都有 Skip Connection 和 Layer Norm） │
└─────────────────────────────────────────┘
  ↓ 输出：理解包（上下文向量序列）
  ↓
┌─────────────────────────────────────────┐
│           Decoder（吐出）                │
│  ┌─────────────────────────────────┐    │
│  │  Masked Self-Attention          │    │
│  └─────────────────────────────────┘    │
│  ┌─────────────────────────────────┐    │
│  │  Encoder-Decoder Attention      │    │
│  └─────────────────────────────────┘    │
│  ┌─────────────────────────────────┐    │
│  │  Feed-Forward Network          │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
  ↓
逐词生成输出（直到出现 <end> 标记）
```

### QA Pipeline 速查卡

```
问题
  ↓
Retriever（在海量文档里找 top-k 最相关的文档）
  ↓
Reader（从这些文档里精确抠出答案片段）
  ↓
答案
```

### 模型家族速查卡

| 模型 | 架构 | 适合任务 | 代表 |
|------|------|---------|------|
| BERT | Encoder-only | 理解、分类、抽取 | BERT-base, RoBERTa |
| GPT | Decoder-only | 生成、续写、对话 | GPT-2, GPT-3 |
| T5 | Encoder-Decoder | 翻译、摘要、问答 | T5-base, Flan-T5 |

## 四、各章工具速查

### 第 1 章（Transformer 解剖课）

**核心概念**
- Encoder = 读懂
- Decoder = 吐出
- Self-Attention = 动态调整身份

**判断模型类型的方法**
- 看架构图：只有 Encoder 堆 → Encoder-only；只有 Decoder 堆 → Decoder-only；两者都有 → Encoder-Decoder

**常见模型对照**
- BERT → Encoder-only
- GPT → Decoder-only
- T5 → Encoder-Decoder

---

### 第 2 章（问答系统实战）

**Haystack 最小代码骨架**

```python
from haystack.document_stores import InMemoryDocumentStore
from haystack.nodes import Retriever, Reader
from haystack.pipelines import ExtractiveQAPipeline

# 1. 建数据库
document_store = InMemoryDocumentStore()
document_store.write_documents([
    {"content": "你的评论文本", "meta": {"source": "xxx"}}
])

# 2. 选 Retriever
retriever = Retriever(document_store=document_store)

# 3. 选 Reader
reader = Reader(model_name_or_path="deepset/roberta-base-squad2")

# 4. 组装 Pipeline
pipe = ExtractiveQAPipeline(reader, retriever)

# 5. 提问
result = pipe.run(query="你的问题", params={"Retriever": {"top_k": 3}, "Reader": {"top_k": 1}})
print(result["answers"][0].answer)
```

**评估指标速记**
- **Hit Rate**：前 k 个结果里有没有命中答案文档
- **MRR**：答案文档平均排第几，越靠前越高
- **Exact Match (EM)**：抠出来的答案跟标准答案完全一样
- **F1**：抠出来的答案跟标准答案的词重合度

**调优方向**
- Retriever 不准：换Embedding模型、加过滤规则、调整 top_k
- Reader 不准：换更大模型、fine-tune 领域数据
- 整体不准：增加更多文档、清洗数据质量

### 第 3 章（未来已来）

**Scaling Law 三要素**
- 模型参数量 ↑ → 能力 ↑，成本 ↑↑
- 训练数据量 ↑ → 能力 ↑，数据成本 ↑
- 训练算力 ↑ → 训练快/模型大，电费 ↑

**效率改良方向**
- Sparse Attention：少算一点，快一点
- Linearized Attention：换算法，让长文本能跑

**多模态入门路径**
- 文本：用 Hugging Face 的 `transformers` 库
- 图像：ViT、CLIP
- 语音：Whisper
- 图文混合：Flamingo、BLIP
