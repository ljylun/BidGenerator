# QA Checklist

## 必过项

- 是 16:9 横版。
- 背景是干净白底。
- 画面中有「大袖」IP 角色——无面人，头部是留白圆圈或极简斗笠剪影，无五官无发型，由两到三个流畅色块组成，核心视觉符号是两只夸张宽大垂坠的交领大袖，轮廓有东方白描或书法飞白质感。
- 「大袖」承担核心动作，不只是装饰——它在用袖子或衣襟执行甩、卷、抛、藏、撑、扫、劈等动作，参与构图。
- 「大袖」必须与画面中的线条、文字、方框产生物理上的接触和参与，不能悬空在一旁。
- 没有复刻旧案例构图，而是为当前文章生成了新的结构隐喻。
- 画面严谨、克制、精准，有"用基础几何搭建逻辑"的建筑学美感。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读，像建筑师在蓝图上的墨水标注。
- 橙 / 棕黄只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果（像红笔或印章）。
- 蓝色只用于补充说明、反馈或系统状态。
- 「大袖」有明确的结构动作：长袖善舞连接模块、袖里乾坤容纳杂物、顺水推舟引导路径、垂衣拱手承重支撑、掩面反思表示断点、披荆斩棘划分边界。
- 「大袖」通过服饰的物理特性（甩、卷、抛、藏、撑、扫）来表达逻辑，而非文字解释。
- 「大袖」本体采用高纯度中国传统色单色（朱砂红、曜石黑、石绿等），与现代黑白图表形成反差。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有"常见坑 / Workflow / 系统架构图 / 路线图"等标题。
- 「大袖」有五官、表情、发型或拟人化特征（看起来像 Q 版古风娃娃或萌系角色）。
- 「大袖」有复杂的汉服绣花、配饰（玉佩、发簪、流苏）或过多褶皱。
- 「大袖」只是穿着汉服抱剑靠在方框旁边看，没有用袖子或衣襟参与构图。
- 画面堆砌了祥云、灯笼、折扇等符号，「大袖」不是唯一的中国元素。
- 「大袖」悬空——没有与画面中的线条、文字、方框产生物理接触和参与。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太花哨、太可爱，没有严肃的构成感。
- 和 `assets/examples/` 里的旧案例构图过于相似。
- 「大袖」只是漂浮在画面中当色块平衡构图，没有承担实际的"结构功能"。
- 袖子看起来柔软无骨，没有毛笔顿挫感和风骨。
- 颜色超过 4 种，或使用了渐变/低饱和度色彩混杂。

## 迭代方法

- 太普通：让「大袖」承担更具体的服饰动作，加入一个奇怪但成立的袖子形变隐喻。
- 太复杂：删减元素，只保留一个核心动作和 3-5 个短标注。
- 太可爱：强调无五官、无表情、no cute、no mascot、严肃构成感，确保袖子有风骨有顿挫感，不圆润不萌系。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成「大袖」用袖子搭建场景。
- 太像旧案例：保留核心意思，换掉主物件和「大袖」的服饰动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。
- 太花哨：回归纯色块、硬边缘、极简，去掉一切装饰性元素。
- 「大袖」没参与动作：让「大袖」正在执行长袖善舞、袖里乾坤、顺水推舟、垂衣拱手等核心结构动作，而不是旁边站着。
- 「大袖」悬空：让它必须与画面中的线条、文字、方框产生物理接触和参与。
- 袖子太软：加强轮廓的毛笔顿挫感，让衣服线条有风骨。

## 交付判断

高质量图应该让读者先觉得"简洁有力"，然后 1 秒内看懂结构。画面应该有严谨的构成感——像是有人真的用「大袖」的服饰和几何块在白纸上搭建出了一个逻辑支撑系统。

如果去掉「大袖」，画面里那些原本飘逸、流动的中式线条逻辑（如弧形连线、留白过渡）瞬间塌陷，变成一张毫无美感的普通表格，说明「大袖」成功融入了结构；如果它只是个好看的汉服色块点缀，没有承担实际的"结构功能"，说明太装饰了，需重写提示词，让「大袖」成为构建或破坏逻辑的动作主体。

如果第一眼像教程页或花哨海报，而不是白纸上的极简几何构成草图，就不合格。
