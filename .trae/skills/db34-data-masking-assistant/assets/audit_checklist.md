# 数据脱敏审计检查清单

本检查清单旨在辅助审计人员对数据脱敏过程进行合规性审查，依据《DB34/T 政务数据 第2部分：脱敏技术规范》的基本要求和流程制定。

## 1. 脱敏基本要求检查

请核查以下脱敏基本要求是否得到满足：

| 检查项 | 描述 | 符合性 (是/否/不适用) | 备注 |
| :----- | :--- | :-------------------- | :--- |
| **不可恢复性** | 是否有效降低或去除敏感数据被恢复的风险？ | | |
| **数据可用性** | 脱敏后的数据是否仍能满足预期目的和业务需求？ | | |
| **目的符合性** | 脱敏数据是否尽量满足其预期目的？ | | |
| **法律合规性** | 脱敏策略是否符合国家法律法规与相关标准？ | | |
| **信息不泄露** | 原始数据脱敏处理后，是否不泄露法定敏感信息，无法倒推或重建？ | | |
| **自动化与可重复** | 脱敏过程是否通过自动化实现且可重复执行？ | | |
| **结果一致性** | 在合格输入条件下，无论脱敏多少次，最终结果是否相同？ | | |
| **规则灵活性** | 脱敏规则是否支持灵活配置，同一规则在不同脱敏条件生成不同结果？ | | |
| **特征覆盖** | 脱敏后的数据是否覆盖主体信息的特征（类型、长度、大小、值域），并保留有意义信息？ | | |
| **自动化处理** | 脱敏是否通过自动化实现，可重复执行？ | | |
| **分类与预案** | 处理前是否对数据集信息进行分类，并明确变更影响及应急预案？ | | |
| **审计机制** | 脱敏服务是否纳入安全审计机制，记录并可追踪分析？ | | |
| **代码安全** | 脱敏代码和模块是否经过安全审查，确保无漏洞和后门？ | | |

## 2. 脱敏流程检查

请核查数据脱敏流程的各个步骤是否得到有效执行：

| 检查项 | 描述 | 符合性 (是/否/不适用) | 备注 |
| :----- | :--- | :-------------------- | :--- |
| **敏感数据发现** | 是否已对组织拥有的数据进行梳理与分类，并识别出敏感数据？ | | |
| **脱敏需求确认** | 是否已明确脱敏目的、范围、字段内容和使用时间，并符合脱敏申请要求？ | | |
| **敏感数据标识** | 是否已利用技术工具对敏感数据进行精准标识和定位？ | | |
| **脱敏方案制定** | 是否已针对敏感字段制定了合适的脱敏技术和形态（静态/动态）？ | | |
| **脱敏操作与记录** | 是否已执行脱敏操作，并对操作行为进行了记录存档？ | | |
| **脱敏过程审计** | 是否已定期组织对脱敏过程的审计？ | | |
| **效果评估与改进** | 是否已收集和整理脱敏过程数据，监控稳定性与业务影响，并持续改进？ | | |
