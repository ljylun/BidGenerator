# DB34 数据脱敏技术规范核心要点

## 1. 规范概述

《DB34/T 政务数据 第2部分：脱敏技术规范》是安徽省地方标准，旨在规范非涉密政务信息系统中结构化数据的数据脱敏工作。它涵盖了数据脱敏的基本要求、技术、策略和流程。

## 2. 核心概念

*   **数据脱敏（Data Masking）**: 通过处理原始数据以屏蔽敏感数据的一种保护方法。
*   **敏感数据（Sensitive Data）**: 泄露、修改、破坏或丢失可能造成损害的数据。
*   **静态数据脱敏（Static Data Masking）**: 对存储数据进行脱敏并持久化。
*   **动态数据脱敏（Dynamic Data Masking）**: 实时对访问请求的数据进行脱敏。
*   **数据脱敏策略（Data Masking Policy）**: 根据场景选择脱敏技术。

## 3. 基本要求

脱敏应遵循以下原则：

1.  **不可恢复性**: 降低敏感数据被恢复的风险，确保原始敏感信息不泄露。
2.  **可用性**: 确保脱敏后的数据仍能满足预期目的和业务需求。
3.  **一致性**: 在合格输入条件下，无论脱敏多少次，结果应相同。
4.  **可配置性**: 脱敏规则应灵活配置，支持不同条件下的不同结果。
5.  **可审计性**: 脱敏服务应纳入安全审计机制，记录并可追溯。
6.  **安全性**: 对脱敏代码和模块进行安全审查，确保无漏洞。

## 4. 脱敏技术分类

规范将脱敏技术分为以下几类：

| 技术大类 | 描述 | 典型方法 |
| :------- | :--- | :------- |
| **密码技术** | 遵循国家密码管理要求，保护数据。 | 确定性加密、保序加密、保留格式加密、同态加密、同态密替换 |
| **抗乱技术** | 通过干扰原始数据降低识别性，保持分布特征。 | 唯一值映射、排序映射、重排、混淆、固定偏移、局部混淆、乱序、随机值替换、散列、保留随机、均化 |
| **泛化技术** | 在保留语义或统计特征前提下，用粗粒度新值替换。 | 截取掩蔽、截断、顶尾与底尾编码、规整、变换 |
| **抑制技术** | 移除或隐藏原始数据中的部分信息。 | 遮盖、掩码/屏蔽、局部抑制、记录抑制 |
| **随机化技术** | 通过随机修改属性值，提升不可逆性。 | 噪声添加、置换、微聚集 |
| **有损技术** | 损失部分数据内容以达到脱敏效果。 | 限制返回行数 |

## 5. 脱敏流程

标准的脱敏流程包括七个步骤：

1.  **发现敏感数据**: 梳理和分类组织拥有的数据。
2.  **确认脱敏需求**: 明确脱敏目的、范围、字段和时间。
3.  **敏感数据标识与确认**: 识别敏感数据位置和精准定位。
4.  **制定脱敏方案**: 针对敏感字段制定技术和形态。
5.  **脱敏操作与记录存档**: 执行脱敏并记录操作行为。
6.  **脱敏过程审计**: 定期组织过程审计。
7.  **评估脱敏效果并改进**: 监控稳定性、业务影响并持续改进。

## 6. 应用场景与技术映射（附录 C 总结）

规范提供了详细的脱敏技术与应用场景的映射关系，指导用户选择合适的脱敏方法。例如：

*   **数据分析**: 重排、关系映射、遮盖、偏移取整、随机值替换、截断、泛化、掩码屏蔽。
*   **开发测试**: 散列、加密。
*   **数据开放**: 匿名、泛化、掩码屏蔽。
*   **数据库运维**: 差分隐私。
*   **群体信息统计**: 均化。

这些映射关系是技能进行方案推荐的核心依据。
