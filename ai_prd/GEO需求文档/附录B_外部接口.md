# 附录B 外部系统接口规格

本附录定义了系统与所有外部平台、服务和数据源之间的接口规范，包括接口清单、详细交互流程、安全要求及版本管理策略。

---

## B.1 接口清单

| 序号 | 接口名称 | 说明 | 方向 | 依赖系统 | 数据流 |
|------|----------|------|------|----------|--------|
| 1 | AI 平台数据采集接口 | 从 ChatGPT、Perplexity、Gemini 等 AI 平台采集品牌提及数据与引用信息 | 入站 | AI 搜索平台 API | AI 平台 → 本系统数据采集模块 |
| 2 | 大模型调用接口 | 调用 LLM（GPT-4/Claude/Gemini）进行内容分析、语义理解与优化建议生成 | 出站 | 大模型服务 API | 本系统 → LLM 服务 → 返回分析结果 |
| 3 | 向量数据库接口 | 向 Milvus/Pinecone 等向量数据库写入和查询内容嵌入向量，支撑语义检索 | 出站 | 向量数据库服务 | 本系统 ↔ 向量数据库（读写双向） |
| 4 | 图数据库接口 | 向 Neo4j/JanusGraph 写入知识图谱实体与关系，支撑实体关联分析 | 出站 | 图数据库服务 | 本系统 ↔ 图数据库（读写双向） |
| 5 | 消息推送接口 | 向企业微信、钉钉、Slack、邮件等渠道推送告警通知与报告 | 出站 | 消息推送服务 | 本系统 → 推送服务 → 用户终端 |
| 6 | 文件存储接口 | 向对象存储（OSS/S3/MinIO）上传和下载报告、内容文件与配置 | 出站 | 对象存储服务 | 本系统 ↔ 对象存储（读写双向） |
| 7 | 第三方数据接入接口 | 从 SEO 工具（Ahrefs/SEMrush）、社交媒体平台、行业数据库获取补充数据 | 入站 | 第三方数据平台 API | 第三方平台 → 本系统数据采集模块 |
| 8 | 开放 API | 对外暴露 RESTful API，供合作伙伴或内部其他系统调用本平台能力 | 入站/出站 | API 网关 | 外部系统 ↔ API 网关 ↔ 本系统服务 |

## B.2 接口详细说明

### B.2.1 AI 平台数据采集接口

#### 触发时机
- **定时触发**：每日凌晨 02:00 执行全量数据采集
- **增量触发**：每 30 分钟执行一次增量数据拉取
- **手动触发**：用户通过管理后台手动发起采集任务

#### 请求条件
- 接口密钥（API Key）有效且未过期
- 目标 AI 平台服务状态正常（健康检查通过）
- 当前无同类型采集任务在执行（防并发冲突）
- 采集配额未超出平台限制

#### 成功处理流程
1. 系统向 AI 平台 API 发送认证请求，获取访问令牌
2. 按配置的关键词列表和品牌实体列表发起搜索查询
3. 采集返回的回答内容、引用来源、品牌提及信息
4. 对采集数据进行去重、格式标准化和 NER 实体识别
5. 将结构化数据存储至数据仓库，更新采集状态日志
6. 触发下游语义分析任务队列

#### 失败处理流程
1. 记录失败日志，包含错误码、时间戳、请求参数快照
2. 判断失败类型：
   - **网络超时**：自动重试（见重试机制）
   - **认证失败**：暂停采集任务，发送告警通知管理员
   - **配额超限**：暂停当日采集，记录超限信息，次日自动恢复
   - **数据格式异常**：跳过异常记录，继续处理后续数据，标记异常记录待人工审核
3. 将失败信息写入采集异常表，供运维人员排查

#### 重试机制
| 参数 | 值 |
|------|-----|
| 最大重试次数 | 3 次 |
| 初始等待间隔 | 5 秒 |
| 退避策略 | 指数退避（5s → 10s → 20s） |
| 最大等待间隔 | 60 秒 |
| 重试条件 | 仅网络超时和 5xx 服务端错误 |
| 不可重试错误 | 4xx 客户端错误（除 429 限流外） |

### B.2.2 大模型调用接口

#### 触发时机
- **内容分析触发**：新内容进入分析队列时自动触发
- **优化建议触发**：用户提交内容优化请求时触发
- **批量处理触发**：定时批量分析任务（每日 06:00）
- **实时查询触发**：用户在前台发起实时分析请求

#### 请求条件
- 调用令牌（Bearer Token）有效
- 当前并发调用数未超出配额上限
- 请求内容长度未超出模型上下文窗口限制
- 内容已通过安全合规检查（无违规内容）

#### 成功处理流程
1. 构造 Prompt，包含系统指令、上下文信息、待分析内容
2. 向 LLM API 发送请求，设置超时时间（单次 ≤ 120 秒）
3. 接收并解析 LLM 返回的结构化响应
4. 对返回结果进行后处理：提取关键指标、格式化输出、校验数据完整性
5. 将分析结果写入数据库，关联原始内容
6. 更新调用统计与配额使用情况
7. 将结果推送至前端或下游处理模块

#### 失败处理流程
1. 捕获异常并分类：
   - **超时**：记录超时日志，标记该请求为待重试
   - **模型过载（503）**：切换到备用模型（Fallback Model）
   - **速率限制（429）**：触发限流退避，加入优先级队列等待
   - **上下文超长（400）**：自动截断内容或拆分为多次调用
   - **内容安全拦截**：记录拦截原因，通知用户修改内容
2. 所有失败请求统一写入 LLM 调用异常表
3. 连续失败超过阈值（5 次/分钟）时触发熔断，暂停该模型调用并切换备用模型

#### 重试机制
| 参数 | 值 |
|------|-----|
| 最大重试次数 | 2 次 |
| 初始等待间隔 | 3 秒 |
| 退避策略 | 指数退避（3s → 6s） |
| 熔断阈值 | 连续 5 次失败或错误率 > 30%（1 分钟窗口） |
| 熔断恢复时间 | 60 秒后进入半开状态 |
| 备用模型切换 | 主模型不可用时自动切换至备用模型 |

## B.3 接口安全规范

### B.3.1 身份认证

| 认证方式 | 适用场景 | 说明 |
|----------|----------|------|
| API Key + Secret | 外部系统调用本系统开放 API | 每个接入方分配唯一 Key/Secret 对，支持密钥轮换 |
| OAuth 2.0 | 第三方平台数据接入 | 使用授权码模式（Authorization Code Flow），Token 有效期 2 小时 |
| JWT Token | 内部模块间通信 | RS256 签名，Token 有效期 30 分钟，支持刷新令牌 |
| mTLS | 高安全级别接口 | 双向 TLS 证书认证，用于 AI 平台数据采集等敏感接口 |
| MFA | 管理后台访问 | 管理后台强制启用 TOTP 多因素认证 |

### B.3.2 数据加密

| 加密场景 | 加密方式 | 说明 |
|----------|----------|------|
| 传输加密 | TLS 1.3 | 所有外部接口强制 HTTPS，禁用 TLS 1.0/1.1 |
| 存储加密 | AES-256 | 数据库敏感字段（API Key、用户信息）加密存储 |
| 密钥管理 | KMS/HSM | 加密密钥通过密钥管理系统统一管理，支持密钥轮换 |
| 日志脱敏 | 掩码处理 | 日志中自动脱敏手机号、身份证号、API Key 等敏感信息 |

### B.3.3 流量控制

| 限流策略 | 参数 | 说明 |
|----------|------|------|
| 全局限流 | 10,000 QPS | 系统整体入口流量上限 |
| 接口级限流 | 1,000 QPS/接口 | 单接口流量上限 |
| 用户级限流 | 100 QPS/用户 | 单用户/租户流量上限 |
| 突发流量缓冲 | 允许 20% 短时突发 | 持续超过 5 秒则触发限流 |
| 限流响应 | HTTP 429 + Retry-After | 返回标准限流响应头 |

### B.3.4 审计日志

| 日志项 | 内容 | 保留期限 |
|--------|------|----------|
| 接口调用日志 | 时间戳、调用方、接口名、请求参数摘要、响应状态码、耗时 | 180 天 |
| 认证日志 | 登录时间、IP 地址、认证方式、成功/失败、设备信息 | 365 天 |
| 异常日志 | 错误堆栈、请求快照、影响范围、处理状态 | 365 天 |
| 数据访问日志 | 访问者、访问时间、数据范围、操作类型 | 365 天 |

## B.4 接口版本管理

### B.4.1 版本策略

| 策略项 | 说明 |
|--------|------|
| 版本标识 | URL 路径版本号，如 `/api/v1/`、`/api/v2/` |
| 版本号规则 | 语义化版本（SemVer）：主版本.次版本.修订号 |
| 主版本升级 | 不兼容的 API 变更（如删除字段、修改数据结构） |
| 次版本升级 | 向后兼容的功能新增（如新增可选参数、新增接口端点） |
| 修订号升级 | 向后兼容的问题修复（如 Bug 修复、性能优化） |
| 预发布版本 | 使用 `-alpha`/`-beta`/`-rc` 后缀标识，如 `/api/v2.0.0-beta/` |

### B.4.2 向后兼容性

| 规则 | 说明 |
|------|------|
| 新增字段 | 必须为可选字段，不影响已有调用方 |
| 废弃字段 | 通过 `Deprecation` 响应头提前通知，保留至少 6 个月兼容期 |
| 删除字段 | 仅允许在主版本升级中执行，需提前 90 天发布迁移指南 |
| 枚举值变更 | 新增枚举值需兼容旧版本，删除枚举值需主版本升级 |
| 响应格式 | 主版本内保持响应结构稳定，变更需次版本升级 |

### B.4.3 版本生命周期

| 阶段 | 说明 | 时间要求 |
|------|------|----------|
| 当前版本 | 推荐使用的最新稳定版本 | — |
| 维护版本 | 上一个主版本，继续提供安全修复 | 当前版本发布后 12 个月内 |
| 废弃版本 | 仅记录日志提醒，不再修复 Bug | 维护期结束后 3 个月 |
| 下线版本 | 停止服务，返回 410 Gone | 废弃期结束后下线 |

### B.4.4 版本协商机制

- 客户端通过 `Accept` 头指定版本：`Accept: application/vnd.mfs-geo.v1+json`
- 未指定版本时默认使用当前最新稳定版本
- 请求已下线版本时返回 `410 Gone` 并附带迁移指引链接
- 所有响应包含 `X-API-Version` 头，标明实际响应版本
- 废弃版本响应额外包含 `Deprecation` 头和 `Sunset` 头（标明下线日期）
