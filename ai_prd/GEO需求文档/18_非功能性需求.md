# 18. 非功能性需求

> 本章定义GEO系统的非功能性需求，涵盖性能、可用性、安全、兼容性、可扩展性和合规性六大维度。这些需求是系统质量的保障基线，所有功能模块的设计和实现均须满足本章规定的要求。

---

## 18.1 性能要求

| 编号 | 指标名称 | 要求值 | 说明 | 测量方法 |
|------|----------|--------|------|----------|
| PR-01 | 页面加载时间 | ≤2秒 | 首页及核心功能页面在正常网络环境（带宽≥10Mbps）下的首次加载时间 | 使用Lighthouse/PageSpeed Insights测量，取P75值 |
| PR-02 | API响应时间 | ≤500毫秒 | 95%的API请求响应时间不超过500ms（不含AI平台外部API调用） | APM工具监控，统计P95值 |
| PR-03 | 语义匹配准确率 | ≥99% | 品牌关键词与AI平台回答内容的语义匹配准确率 | 使用标注数据集（≥1000条）进行离线评估 |
| PR-04 | Prompt生成时间 | ≤5秒 | 基于模板和上下文生成优化Prompt的端到端时间 | 端到端计时，含AI模型调用时间 |
| PR-05 | 知识库检索时间 | ≤1秒 | 知识库全文检索和向量检索的响应时间 | 在知识库数据量达到10万条时测量P95值 |
| PR-06 | 并发用户数 | ≥1000 | 系统支持同时在线用户数≥1000，且核心功能响应时间不超标 | 使用JMeter/Locust进行压力测试 |
| PR-07 | 数据同步延迟 | ≤5分钟 | 从AI平台数据变更到GEO系统完成同步的最大延迟 | 端到端数据同步链路监控 |
| PR-08 | 报告生成时间 | ≤30秒 | 生成一份完整诊断报告（含图表）的最大时间 | 在14平台全量数据下测量 |
| PR-09 | 数据库查询时间 | ≤200毫秒 | 单表百万级数据量的常规查询响应时间 | 数据库慢查询日志监控 |
| PR-10 | 文件上传速度 | ≥1MB/s | 知识库文件上传（单文件≤100MB）的最低传输速度 | 网络传输速率监控 |

**性能分级策略**：

| 响应时间 | 评级 | 处理策略 |
|----------|------|----------|
| ≤500ms | 优秀 | 无需优化 |
| 500ms-2s | 良好 | 纳入优化计划 |
| 2s-5s | 一般 | 优先优化 |
| >5s | 较差 | 立即优化 |

## 18.2 可用性要求

| 编号 | 指标名称 | 要求值 | 说明 |
|------|----------|--------|------|
| AR-01 | 系统可用性 | ≥99.9% | 月度可用性不低于99.9%，即每月计划外停机时间≤43.8分钟 |
| AR-02 | 年非计划停机时间 | ≤8.76小时 | 全年累计非计划停机时间不超过8.76小时 |
| AR-03 | RTO（恢复时间目标） | ≤30分钟 | 系统发生故障后，从故障发生到系统恢复可用的最大时间 |
| AR-04 | RPO（恢复点目标） | ≤5分钟 | 系统发生故障后，允许的最大数据丢失时间窗口 |
| AR-05 | 计划维护窗口 | 每月≤2小时 | 系统计划内维护时间，需提前72小时通知用户 |
| AR-06 | 故障检测时间 | ≤1分钟 | 从故障发生到监控系统检测到故障的最大时间 |
| AR-07 | 自动恢复能力 | 核心服务≥95% | 核心服务故障后自动恢复的成功率不低于95% |

**可用性等级定义**：

| 等级 | 可用性 | 年停机时间 | 适用场景 |
|------|--------|-----------|----------|
| 一级 | 99.99% | ≤52.6分钟 | 核心诊断引擎 |
| 二级 | 99.9% | ≤8.76小时 | 数据采集与报告生成 |
| 三级 | 99.5% | ≤43.8小时 | 辅助功能模块 |

**容灾策略**：
- 核心服务采用多可用区部署，任一可用区故障可自动切换
- 数据库采用主从复制，主库故障后从库自动接管（切换时间≤30秒）
- 关键数据实时备份至异地容灾中心
- 定期执行灾难恢复演练（每季度至少1次）

## 18.3 安全要求

### 18.3.1 数据传输安全

| 编号 | 要求 | 说明 |
|------|------|------|
| SR-01 | TLS 1.2+加密 | 所有客户端与服务器之间的通信必须使用TLS 1.2或更高版本加密 |
| SR-02 | AES-256数据加密 | 敏感数据（API密钥、用户凭证等）在存储时必须使用AES-256加密 |
| SR-03 | 证书管理 | 使用受信任CA签发的SSL证书，证书到期前30天自动提醒更新 |
| SR-04 | API传输签名 | 所有API请求需进行HMAC-SHA256签名验证，防止请求篡改 |

### 18.3.2 身份认证与访问控制

| 编号 | 要求 | 说明 |
|------|------|------|
| SR-05 | 多因素认证（MFA） | 管理员账户和敏感操作必须启用MFA（支持TOTP/短信/邮件验证） |
| SR-06 | RBAC+ABAC权限模型 | 采用基于角色的访问控制（RBAC）结合基于属性的访问控制（ABAC），支持细粒度权限管理 |
| SR-07 | 密码策略 | 密码长度≥8位，必须包含大小写字母、数字和特殊字符，90天强制更换 |
| SR-08 | 会话管理 | 会话超时时间≤30分钟，支持强制下线、并发登录限制（同一账户最多3个并发会话） |
| SR-09 | OAuth2.0/API Key认证 | 第三方集成使用OAuth2.0或API Key认证，API Key支持轮换和撤销 |

### 18.3.3 审计与日志

| 编号 | 要求 | 说明 |
|------|------|------|
| SR-10 | 审计日志保留 | 审计日志保留期限≥180天，包含操作人、操作时间、操作内容、操作结果、IP地址 |
| SR-11 | 日志完整性 | 审计日志采用防篡改机制（哈希链/WORM存储），确保日志不可篡改 |
| SR-12 | 异常行为检测 | 自动检测异常登录、异常操作频率、异常数据访问等安全事件 |

### 18.3.4 数据保护

| 编号 | 要求 | 说明 |
|------|------|------|
| SR-13 | 数据脱敏 | 敏感数据（手机号、邮箱、身份证号等）在展示时必须脱敏处理 |
| SR-14 | 数据分类分级 | 按照数据敏感程度分为公开、内部、机密、绝密四个等级，实施差异化保护措施 |
| SR-15 | 数据备份 | 每日全量备份+实时增量备份，备份数据加密存储，保留30天 |
| SR-16 | 数据删除 | 用户注销账户后，个人数据在30天内彻底删除（法律要求保留的除外） |

## 18.5 可扩展性要求

| 编号 | 要求 | 说明 |
|------|------|------|
| SR-01 | 水平扩展 | 应用服务层支持水平扩展（无状态设计），通过增加服务器节点即可提升处理能力 |
| SR-02 | 数据库扩展 | 支持数据库读写分离和分库分表，单表数据量超过500万时自动触发分表策略 |
| SR-03 | 插件机制 | 采用插件化架构，AI平台对接、评分模型、报告模板等核心组件支持插件化扩展 |
| SR-04 | RESTful API | 所有对外接口遵循RESTful设计规范，支持版本化管理（v1/v2/...） |
| SR-05 | 消息队列 | 核心业务流程（数据采集、报告生成）采用消息队列异步处理，支持削峰填谷 |
| SR-06 | 缓存策略 | 支持多级缓存（本地缓存+Redis分布式缓存），热点数据缓存命中率≥90% |
| SR-07 | 配置化 | 业务规则、评分权重、告警阈值等参数支持后台配置化调整，无需代码变更 |
| SR-08 | AI模型可替换 | 语义匹配、情感分析等AI模型支持热切换，切换过程不影响业务连续性 |

**扩展性指标**：

| 指标 | 当前容量 | 扩展目标 | 扩展方式 |
|------|----------|----------|----------|
| 并发用户 | 1000 | 10000 | 水平扩展 |
| 数据量 | 1TB | 100TB | 分库分表+对象存储 |
| AI平台对接 | 14个 | 50个 | 插件化扩展 |
| 日处理任务 | 10000 | 100000 | 消息队列+弹性伸缩 |

## 18.6 合规要求

> 本系统须符合《信息安全技术 网络安全等级保护基本要求》（GB/T 22239-2019）中**等保三级**的相关要求，以下列出关键合规项。

### 18.6.1 身份鉴别

| 编号 | 合规要求 | 实现方式 |
|------|----------|----------|
| CR-01 | 用户身份唯一标识 | 每个用户分配唯一用户ID，与身份凭证绑定 |
| CR-02 | 身份鉴别机制 | 支持用户名+密码+多因素认证（MFA）的组合鉴别方式 |
| CR-03 | 鉴别失败处理 | 连续5次登录失败后锁定账户30分钟，并记录安全日志 |
| CR-04 | 密码复杂度 | 密码长度≥8位，包含大小写字母、数字、特殊字符中的至少3类 |

### 18.6.2 访问控制

| 编号 | 合规要求 | 实现方式 |
|------|----------|----------|
| CR-05 | 权限最小化原则 | 用户仅被授予完成工作所需的最小权限集 |
| CR-06 | 权限分离 | 系统管理员、安全管理员、审计管理员三权分立 |
| CR-07 | 默认拒绝策略 | 未明确授权的访问请求一律拒绝 |
| CR-08 | 权限定期审查 | 每季度审查一次用户权限，及时清理过期权限 |

### 18.6.3 安全审计

| 编号 | 合规要求 | 实现方式 |
|------|----------|----------|
| CR-09 | 审计覆盖范围 | 覆盖用户登录、权限变更、数据操作、系统配置变更等关键事件 |
| CR-10 | 审计记录内容 | 包含事件时间、事件类型、主体标识、客体标识、事件结果 |
| CR-11 | 审计记录保护 | 审计记录采用防篡改机制，保留期限≥180天 |
| CR-12 | 审计报告 | 支持按时间范围、事件类型、用户等维度生成审计报告 |

### 18.6.4 数据脱敏

| 编号 | 合规要求 | 实现方式 |
|------|----------|----------|
| CR-13 | 敏感数据识别 | 自动识别手机号、邮箱、身份证号、银行卡号等敏感数据 |
| CR-14 | 展示脱敏 | 敏感数据在非授权页面展示时进行脱敏处理（如138****1234） |
| CR-15 | 导出脱敏 | 数据导出时默认启用脱敏，需审批后方可导出明文数据 |
| CR-16 | 脱敏规则配置 | 支持按用户角色和数据等级配置差异化脱敏规则 |

### 18.6.5 文件安全

| 编号 | 合规要求 | 实现方式 |
|------|----------|----------|
| CR-17 | 文件上传安全 | 限制上传文件类型（白名单），单文件≤100MB，上传后病毒扫描 |
| CR-18 | 文件存储安全 | 上传文件重命名存储，存储目录与Web根目录隔离 |
| CR-19 | 文件访问控制 | 文件访问需鉴权，防止未授权访问和目录遍历攻击 |
| CR-20 | 文件删除安全 | 文件删除采用逻辑删除+定期物理删除策略 |

### 18.6.6 数据传输安全

| 编号 | 合规要求 | 实现方式 |
|------|----------|----------|
| CR-21 | 传输加密 | 所有数据传输使用TLS 1.2+加密 |
| CR-22 | 完整性校验 | 关键数据传输附加HMAC签名，接收端验证完整性 |
| CR-23 | API安全 | API接口实施频率限制（Rate Limiting），防止暴力破解和DDoS攻击 |
| CR-24 | 密钥管理 | 加密密钥定期轮换（每90天），密钥存储使用专用密钥管理系统（KMS） |

### 18.6.7 其他合规要求

| 编号 | 合规要求 | 说明 |
|------|----------|------|
| CR-25 | 隐私政策 | 系统须提供隐私政策页面，明确告知用户数据收集和使用方式 |
| CR-26 | 用户数据权利 | 支持用户查询、更正、删除个人数据的权利 |
| CR-27 | 数据跨境 | 用户数据存储在境内服务器，未经审批不得跨境传输 |
| CR-28 | 安全事件响应 | 建立安全事件响应机制，重大安全事件须在24小时内上报 |
