# M08 模块八：营销自动化平台

## 模块定位

| 属性 | 说明 |
|------|------|
| **模块名称** | 营销自动化平台（Marketing Automation Platform） |
| **模块编号** | M08 |
| **系统定位** | GEO 系统的"执行层"，负责可视化搭建自动营销流程，将用户数据洞察转化为可执行、可追踪、可优化的全链路营销动作 |
| **优先级** | P2 |
| **竞品参考** | GMA（Growth Marketing Automation）增长营销自动化平台 |
| **关联模块** | M03 用户画像引擎、M04 人群圈选平台、M05 触达通道管理、M06 数据分析看板 |

> **模块概述**：营销自动化平台是 GEO 系统中连接"用户洞察"与"营销执行"的核心枢纽。平台提供可视化流程画布，让运营人员无需编码即可搭建复杂的用户旅程，实现从人群筛选、多渠道触达、频控管理到效果分析的全流程自动化闭环。

## 14.1 功能清单

| 编号 | 功能名称 | 优先级 | 功能描述 |
|------|----------|--------|----------|
| M08-F01 | 可视化流程画布 | P2 | 提供拖拽式流程编排界面，支持节点连线、条件分支、并行路径，运营人员可直观搭建用户旅程，无需编码 |
| M08-F02 | 用户精准筛选 | P2 | 对接 M03 用户画像引擎，支持多维度标签组合、行为条件筛选、时间窗口限定，精准锁定目标人群 |
| M08-F03 | 多渠道触达 | P2 | 支持短信、微信模板消息、站内弹框、APP 推送、邮件等通道的统一配置与分发，一次活动覆盖全渠道 |
| M08-F04 | 全局触达管理 | P2 | 全局频控规则引擎，支持按用户维度设置触达上限（日/周/月），跨活动去重，防止过度打扰 |
| M08-F05 | 推送勿扰 | P2 | 支持配置勿扰时段（如夜间免打扰），支持用户自定义免打扰偏好，合规触达 |
| M08-F06 | A/B 对照组 | P2 | 支持在活动中配置多组对照实验，自动分流用户，对比不同文案/渠道/时段的转化效果 |
| M08-F07 | 动态内容设置 | P2 | 支持模板变量替换、个性化字段插入、条件内容块，实现千人千面的营销内容 |
| M08-F08 | 实时效果分析 | P2 | 提供实时数据看板，展示触达量、打开率、点击率、转化率等核心指标，支持按渠道/时段/人群维度下钻 |
| M08-F09 | 营销活动管理 | P2 | 活动的全生命周期管理：创建、审核、上线、暂停、结束、归档，支持活动模板复用 |
| M08-F10 | 自动化规则引擎 | P2 | 基于事件触发（用户行为/时间/数据变化）的自动化规则配置，支持"如果…就…"逻辑链，实现无人值守的持续营销 |

## 14.3 交互说明

| 交互场景 | 触发条件 | 交互流程 | 预期结果 |
|----------|----------|----------|----------|
| **新建活动** | 点击"+ 新建活动"按钮 | ① 弹出活动基础信息弹窗（名称、描述、时间范围）→ ② 选择活动模板或从空白创建 → ③ 进入流程画布编辑页面 | 活动创建成功，进入画布编辑状态，活动状态为"草稿" |
| **流程画布编辑** | 在画布上操作节点和连线 | ① 从左侧节点面板拖拽节点至画布 → ② 点击节点打开右侧配置面板 → ③ 拖拽节点端口创建连线 → ④ 连线支持条件分支配置（满足条件/不满足条件）→ ⑤ 支持节点复制、删除、撤销/重做 | 流程以 DAG（有向无环图）结构保存，自动校验流程完整性（必须有开始节点、无孤立节点、无循环） |
| **人群筛选** | 配置"人群筛选"节点 | ① 选择人群来源（M04 已有人群包 / 实时筛选）→ ② 若实时筛选：配置标签条件（年龄、地域、行为、标签）→ ③ 预览人群规模 → ④ 支持人群排除（排除已触达/已转化用户） | 人群规模实时预估显示，支持保存为人群包供后续复用 |
| **触达配置** | 配置"触达"节点 | ① 选择触达渠道（短信/微信/弹框/APP推送/邮件）→ ② 选择或创建消息模板 → ③ 配置动态变量（用户名、商品名、优惠券码等）→ ④ 设置发送时间（立即/定时/延迟）→ ⑤ 配置频控规则（继承全局/自定义）→ ⑥ 配置 A/B 对照组（可选） | 触达节点配置完成，预览消息效果，支持发送测试消息验证 |
| **效果查看** | 活动上线后点击"效果查看" | ① 进入实时效果看板 → ② 查看核心指标卡片（触达量、打开率、点击率、转化率、ROI）→ ③ 按渠道/时段/人群维度切换查看 → ④ 查看漏斗转化图 → ⑤ 查看 A/B 对照组对比数据 → ⑥ 支持数据导出 | 数据实时更新（延迟 ≤ 5 分钟），图表可交互下钻，支持导出 CSV/Excel |

## 14.4 错误处理规范

| 错误类型 | 错误场景 | 处理策略 | 用户提示 |
|----------|----------|----------|----------|
| **流程配置错误** | 流程存在孤立节点、缺少开始节点、存在循环依赖 | 保存/上线时自动校验，阻断操作并高亮错误节点 | "流程配置不完整：节点「触达配置」缺少上游连接，请检查后重试" |
| **流程配置错误** | 节点必填参数未配置 | 节点显示红色警告标记，配置面板内联提示 | "请完成节点配置：触达渠道和消息模板为必填项" |
| **人群筛选失败** | 筛选条件过于严格导致人群规模为 0 | 实时预估人群规模，规模为 0 时弹窗确认 | "当前筛选条件未匹配到任何用户，请调整筛选条件" |
| **人群筛选失败** | 人群圈选服务超时或异常 | 自动重试 1 次，失败后提示用户 | "人群筛选服务暂时不可用，请稍后重试或联系技术支持" |
| **触达失败** | 短信/微信等通道发送失败 | 记录失败明细，支持按失败原因分类重试 | "部分消息发送失败（1,234 条），失败原因：通道超时。是否重试？" |
| **触达失败** | 消息模板变量解析失败 | 使用默认值替换无法解析的变量，记录异常日志 | "消息内容包含无法识别的变量，已使用默认值替代" |
| **频控超限** | 用户触达次数超过全局频控上限 | 自动跳过超限用户，记录跳过数量 | "本次触达跳过 2,567 位已达频控上限的用户，实际触达 47,433 人" |
| **频控超限** | 活动级频控超限 | 在活动维度拦截，提示运营人员 | "该活动今日触达量已达上限（10,000），请调整频控规则或明日再试" |

## 14.5 技术规格

### 14.5.1 流程画布引擎设计

```
┌─────────────────────────────────────────────────────────┐
│                    流程画布引擎架构                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌──────────────┐    ┌──────────────┐    ┌───────────┐ │
│  │  前端画布层   │    │  流程解析层   │    │ 执行引擎  │ │
│  │  (React +   │◀──▶│  (DAG 校验 + │◀──▶│ (异步任务 │ │
│  │   Flow.js)   │    │   拓扑排序)   │    │  调度器)  │ │
│  └──────────────┘    └──────────────┘    └───────────┘ │
│         │                    │                   │      │
│         ▼                    ▼                   ▼      │
│  ┌──────────────┐    ┌──────────────┐    ┌───────────┐ │
│  │  节点配置UI   │    │  流程持久化   │    │ 状态机    │ │
│  │  (动态表单)   │    │  (JSON 存储)  │    │ (活动/节点│ │
│  └──────────────┘    └──────────────┘    │  /用户)   │ │
│                                          └───────────┘ │
└─────────────────────────────────────────────────────────┘
```

**核心设计要点：**

- **节点类型**：开始节点、人群筛选节点、触达节点、条件分支节点、延迟等待节点、A/B 分流节点、结束节点
- **流程存储**：以 JSON 格式存储 DAG 结构，包含节点定义（类型、配置、位置）和连线定义（源节点、目标节点、条件表达式）
- **执行引擎**：基于状态机模型，每个用户实例独立追踪流程进度，支持断点续跑
- **并发控制**：活动级分布式锁，防止同一活动被重复触发

### 14.5.2 用户筛选引擎

| 组件 | 说明 |
|------|------|
| **标签查询服务** | 对接 M03 用户画像引擎，支持实时标签查询，P99 延迟 ≤ 50ms |

| **增量更新** | 支持定时增量更新人群包，捕获新增符合条件的用户 |

```
用户进入触达节点
       │
       ▼
┌──────────────┐    是    ┌──────────────┐
│ 检查用户勿扰  │─────────▶│ 跳过该用户    │
│ 偏好设置     │          │ 记录跳过原因  │

       │ 否
       ▼
┌──────────────┐    是    ┌──────────────┐

└──────┬───────┘          └──────────────┘
       │ 未超限
       ▼
┌──────────────┐    是    ┌──────────────┐

       ▼
┌──────────────┐
│ 检查渠道级    │    是    ┌──────────────┐
│ 频控         │─────────▶│ 跳过该用户    │
└──────┬───────┘          └──────────────┘

       ▼

```

**频控维度：**

| 维度 | 说明 | 存储方案 |
|------|------|----------|
| 全局频控 | 单用户每日/每周/月最大触达次数 | Redis 计数器，Key = `freq:global:{userId}:{date}` |
| 活动频控 | 单活动每日最大触达量 | Redis 计数器，Key = `freq:campaign:{campaignId}:{date}` |
| 渠道频控 | 单渠道每日最大触达量 | Redis 计数器，Key = `freq:channel:{channelId}:{date}` |
| 勿扰时段 | 用户自定义免打扰时间窗口 | 用户偏好表 + 内存缓存 |

### 14.5.5 实时效果计算

| 指标 | 计算方式 | 数据源 | 更新频率 |
|------|----------|--------|----------|
| 触达量 | COUNT(发送记录) | 触达适配器回调 | 实时（≤ 1 分钟） |
| 送达率 | 送达数 / 触达量 × 100% | 通道回执 | 实时（≤ 1 分钟） |
| 打开率 | 打开数 / 送达数 × 100% | 埋点上报 | 近实时（≤ 5 分钟） |
| 点击率 | 点击数 / 打开数 × 100% | 埋点上报 | 近实时（≤ 5 分钟） |
| 转化率 | 转化数 / 触达量 × 100% | 业务系统回调 | 近实时（≤ 5 分钟） |
| ROI | (转化收益 - 触达成本) / 触达成本 × 100% | 财务系统 + 成本计算 | 准实时（≤ 15 分钟） |

**数据管道：** 触达事件 → Kafka 消息队列 → Flink 实时计算 → ClickHouse 存储 → 前端看板查询
