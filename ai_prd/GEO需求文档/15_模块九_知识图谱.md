# M09 模块九：知识图谱引擎

## 模块定位

| 属性 | 说明 |
|------|------|
| **模块名称** | 知识图谱引擎（Knowledge Graph Engine） |
| **模块代号** | M09 |
| **优先级** | **P0** |
| **模块定位** | GEO 系统的"认知基座"，负责知识图谱的构建、存储、查询和推理，为上层业务（商机发现、产业链分析、商圈洞察）提供结构化知识支撑 |
| **竞品参考** | 知识图谱引擎 |
| **依赖模块** | M01 数据采集引擎、M04 自然语言处理引擎、M07 商机发现引擎 |

## 15.1 功能清单

| 编号 | 功能名称 | 优先级 | 说明 |
|------|----------|--------|------|
| M09-F01 | 图谱构建工具 | **P0** | 提供自动化知识图谱构建 Pipeline，支持从多源异构数据（结构化数据库、非结构化文本、半结构化网页）中自动构建知识图谱，支持增量更新与全量重建 |
| M09-F02 | 实体识别与链接 | **P0** | 基于 NER 模型自动识别文本中的实体（企业、产品、人物、地点、行业术语等），并将识别出的实体链接到图谱中的已有实体或新建实体，解决同名消歧与异名合并问题 |
| M09-F03 | 关系抽取与建模 | **P0** | 从文本和结构化数据中自动抽取实体间关系（如"供应""合作""竞争""控股""上下游"等），支持关系属性建模、置信度评分与冲突消解 |
| M09-F04 | 图数据库引擎 | **P0** | 高性能图数据库存储引擎，支持亿级节点/边的大规模图谱存储，提供毫秒级邻域查询、多跳遍历、子图匹配等核心能力，支持分布式水平扩展 |
| M09-F05 | 图谱可视化 | P1 | 提供交互式图谱可视化探索界面，支持力导向图、层次图、地理空间图等多种布局，支持节点/边的筛选、聚合、展开/收起、路径高亮等交互操作 |
| M09-F06 | 图谱查询推理 | P1 | 提供类 Cypher 的图查询语言，支持规则推理（基于业务规则的逻辑推理）和路径推理（最短路径、关键路径、影响力传播路径等），支持自然语言转图查询（NL2Cypher） |
| M09-F07 | 产业链图谱 | P1 | 基于知识图谱自动挖掘和构建产业链上下游关系图谱，支持产业层级划分、关键环节识别、产业链健康度评估，为商机发现提供产业视角 |
| M09-F08 | 商圈分析 | P2 | 基于地理空间维度的知识图谱分析，支持商圈范围划定、商圈竞争格局分析、商圈潜力评估，结合 POI 数据与企业经营数据生成商圈画像 |
| M09-F09 | 图谱质量评估 | P1 | 提供图谱质量多维度评估体系，包括完整性（实体/关系覆盖率）、准确性（抽样校验正确率）、时效性（数据新鲜度）、一致性（冲突检测）等指标，自动生成质量报告 |
| M09-F10 | 图谱导入导出 | P1 | 支持标准图谱数据格式的导入导出（RDF/XML、Turtle、CSV、JSON-LD、Neo4j Dump），支持与外部知识图谱（Wikidata、DBpedia）的实体对齐与数据融合 |

## 15.3 交互说明

| 交互场景 | 触发条件 | 系统行为 | 用户反馈 |
|----------|----------|----------|----------|
| **新建图谱** | 用户点击"新建图谱"，输入图谱名称、描述、数据源配置 | 系统创建空白图谱实例，初始化图数据库 Schema，启动数据采集任务 | 显示构建进度条，完成后跳转至图谱编辑页面 |
| **自动构建** | 用户选择数据源（数据库/API/文件上传），配置映射规则，点击"开始构建" | 系统执行完整构建 Pipeline：数据抽取→实体识别→关系抽取→冲突消解→图谱入库，实时更新进度 | 分阶段展示进度（数据抽取→实体识别→关系抽取→入库），完成后显示构建报告（新增实体数、关系数、冲突数） |
| **手动编辑** | 用户在可视化区域双击节点/边，或在详情面板点击"编辑" | 进入编辑模式，支持修改实体属性、新增/删除节点、绘制新关系、调整关系类型与权重 | 编辑操作实时保存，支持撤销/重做，修改后自动触发关联路径重计算 |

| **质量评估** | 用户点击"质量评估"，选择评估范围（全图/子图）和评估维度 | 系统按指标体系自动评估，生成质量报告（含评分、问题列表、改进建议），以仪表盘形式展示 | 报告支持导出 PDF，问题项可一键定位至图谱中对应节点/边 |

## 15.4 错误处理规范

| 错误场景 | 触发条件 | 处理策略 | 用户提示 |
|----------|----------|----------|----------|
| **实体识别准确率不足** | NER 模型对某批次数据的识别准确率低于阈值（默认 85%） | 自动触发模型降级策略（LLM-NER → BERT-CRF → 规则匹配），将低置信度实体标记为"待人工审核"，推入审核队列 | 弹窗提示："实体识别准确率 78%，低于阈值 85%。已标记 342 条待审核实体，是否前往审核？" |
| **关系抽取冲突** | 同一对实体间存在多条矛盾关系（如同时存在"合作"和"竞争"且置信度接近），或新抽取关系与已有关系冲突 | 启动冲突消解流程：① 按数据源权威性排序；② 按时间戳取最新；③ 计算加权置信度；④ 无法自动消解则标记为冲突待人工处理 | 在图谱中以红色虚线标注冲突关系，详情面板显示冲突详情与消解建议，支持用户手动裁决 |
| **图谱规模过大** | 单次查询涉及的子图节点数超过 10 万，或全图节点数超过 5 亿 | 查询层面：自动启用分页查询与采样策略，限制单次返回节点数（默认 5000）；存储层面：触发自动分片与分区策略，热点子图缓存至内存 | 提示："查询范围过大，已自动启用采样模式（采样率 10%）。如需全量结果，建议使用导出功能分批获取。" |
| **查询超时** | 图查询执行时间超过设定阈值（默认 30s，可配置） | 自动终止超时查询，分析执行计划，推荐优化方案（如添加索引、简化查询路径、缩小查询范围）；对高频超时查询自动创建物化视图 | 提示："查询超时（>30s）。建议：① 缩小查询范围 ② 添加更多过滤条件 ③ 已自动创建索引优化，重试可能更快。" |

## 15.5 技术规格

### 15.5.1 图谱构建 Pipeline

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  数据源   │───▶│  预处理   │───▶│ 实体识别  │───▶│ 关系抽取  │───▶│ 图谱存储  │
│          │    │          │    │          │    │          │    │          │
│• 数据库   │    │• 数据清洗 │    │• NER模型  │    │• 关系分类 │    │• 图数据库 │
│• API接口  │    │• 格式统一 │    │• 实体链接 │    │• 属性抽取 │    │• 索引构建 │
│• 文件上传 │    │• 去重合并 │    │• 消歧合并 │    │• 置信评分 │    │• 版本管理 │
│• 网页抓取 │    │• 分块切片 │    │• 新实体   │    │• 冲突消解 │    │• 增量更新 │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
```

**Pipeline 详细规格：**

| 阶段 | 技术方案 | 关键参数 |
|------|----------|----------|
| 数据源接入 | 支持 JDBC/REST API/FTP/S3/文件上传，统一数据接入层 | 单源接入延迟 < 5s，支持并发 16 源 |
| 预处理 | Apache Spark 分布式清洗，自定义清洗规则引擎 | 处理吞吐 > 100 万条/分钟 |
| 实体识别 | 双模型架构：BERT-CRF（高精度）+ LLM-NER（高召回） | BERT-CRF F1 > 92%，LLM-NER F1 > 88% |
| 关系抽取 | 基于 Prompt 的 LLM 关系抽取 + 规则模板补充 | 关系抽取 F1 > 85%，支持 50+ 种关系类型 |
| 图谱存储 | Neo4j 集群 + 自研分布式图存储引擎（备选） | 写入吞吐 > 10 万节点/秒，查询 P99 < 200ms |

### 15.5.2 NER 模型选型

| 模型方案 | 适用场景 | 优势 | 劣势 | 选型建议 |
|----------|----------|------|------|----------|
| **BERT-CRF** | 通用领域实体识别 | 训练成本低、推理速度快、可解释性强 | 对领域新词识别能力弱 | 作为主力模型，覆盖 80% 常规场景 |
| **LLM-NER（GPT-4/Claude）** | 复杂语境、领域专有实体 | 理解能力强、零样本/少样本能力强 | 成本高、推理速度慢、输出格式不稳定 | 作为补充模型，处理低置信度样本和领域新词 |
| **规则+词典** | 结构化字段、已知实体 | 准确率极高、可控性强 | 覆盖率低、维护成本递增 | 用于已知实体库的快速匹配和校验 |

**NER 模型部署架构：**
- 第一层：规则+词典快速匹配（命中率约 40%，延迟 < 10ms）
- 第二层：BERT-CRF 批量推理（覆盖剩余 60%，延迟 < 50ms/条）
- 第三层：LLM-NER 处理低置信度样本（置信度 < 0.7 的候选实体，延迟 < 2s/条）

### 15.5.3 图数据库选型对比

| 评估维度 | Neo4j（推荐） | 自研图引擎（备选） |
|----------|---------------|---------------------|
| **查询性能** | 原生图存储，邻域查询 O(1)，多跳查询毫秒级 | 取决于底层存储引擎设计 |
| **扩展性** | 因果集群支持读写分离，分片需企业版 | 可自定义分片策略，灵活度高 |
| **生态成熟度** | 生态完善，Cypher 语言标准化，社区活跃 | 需自建生态，长期维护成本高 |
| **运维成本** | 社区版免费，企业版按节点授权 | 研发成本高，但无授权费用 |
| **适用场景** | 节点 < 5 亿，团队规模 < 50 人 | 节点 > 5 亿，有专职图数据库团队 |
| **选型结论** | **Phase 1-2 采用 Neo4j 社区版 + 因果集群** | Phase 3 启动自研引擎预研，逐步替代 |

### 15.5.4 可视化引擎设计

| 布局算法 | 适用场景 | 节点规模上限 | 性能要求 |
|----------|----------|-------------|----------|
| **力导向图（Force-Directed）** | 通用探索、关系网络分析 | < 5,000 节点 | 60fps 流畅交互 |
| **层次图（Dagre/Hierarchical）** | 产业链层级、组织架构 | < 10,000 节点 | 布局计算 < 1s |
| **地理空间图（Geo Map）** | 商圈分析、区域分布 | < 20,000 节点 | 瓦片化渲染，支持缩放 |
| **时间轴图（Timeline）** | 关系演化、事件序列 | < 3,000 节点 | 动画过渡流畅 |

**可视化技术栈：**
- 渲染引擎：D3.js（力导向图）+ AntV G6（地理图/层次图）
- 大规模渲染：WebGL 加速（节点 > 5000 自动切换）
- 交互框架：支持框选、套索选择、滚轮缩放、右键菜单、键盘快捷键

### 15.5.5 查询推理引擎

| 能力层 | 功能 | 技术实现 |
|--------|------|----------|
| **图查询层** | 节点查询、邻域查询、路径查询、子图匹配 | Cypher 查询语言 + 查询优化器（基于代价的索引选择） |
| **规则推理层** | 基于业务规则的逻辑推理（如"若 A 供应 B 且 B 供应 C，则 A 间接供应 C"） | 内置规则引擎（Drools/自研），支持规则配置与热加载 |
| **路径推理层** | 最短路径、关键路径、影响力传播路径、社区发现 | BFS/DFS/Dijkstra 算法 + PageRank/Louvain 社区检测 |
| **NL2Cypher 层** | 自然语言问题 → Cypher 查询语句 | 基于 LLM 的语义解析，结合图谱 Schema 进行约束解码 |

**查询性能目标：**

| 查询类型 | 数据规模 | 目标响应时间 |
|----------|----------|-------------|
| 单节点查询 | 1 亿节点 | < 50ms |
| 2 跳邻域查询 | 1 亿节点 | < 200ms |
| 最短路径（3 跳） | 1 亿节点 | < 1s |
| 规则推理（10 条规则） | 100 万节点 | < 2s |
| NL2Cypher | 1 亿节点 | < 5s |

### 15.5.6 质量评估指标体系

| 评估维度 | 指标名称 | 计算方法 | 目标值 |
|----------|----------|----------|--------|
| **完整性** | 实体覆盖率 | 已识别实体数 / 应识别实体总数 | ≥ 90% |
| **完整性** | 关系覆盖率 | 已抽取关系数 / 应抽取关系总数 | ≥ 85% |
| **完整性** | 属性完整度 | 非空属性数 / 总属性数 | ≥ 80% |
| **准确性** | 实体识别准确率 | 正确识别实体数 / 总识别实体数 | ≥ 92% |
| **准确性** | 关系抽取准确率 | 正确关系数 / 总关系数 | ≥ 85% |
| **准确性** | 实体链接准确率 | 正确链接数 / 总链接数 | ≥ 95% |
| **时效性** | 数据新鲜度 | 1 - (过期实体数 / 总实体数) | ≥ 90% |
| **时效性** | 更新延迟 | 数据变更到图谱更新的时间差 | < 1h（增量） |
| **一致性** | 冲突率 | 冲突关系数 / 总关系数 | < 2% |
| **一致性** | 重复实体率 | 重复实体数 / 总实体数 | < 1% |
