## 1. 产品概述

### 1.1 产品背景

随着大语言模型（LLM）驱动的AI搜索平台（ChatGPT、Perplexity、Gemini、Claude等）快速崛起，用户获取信息的方式正在从传统搜索引擎向AI对话式搜索迁移。企业品牌在这些AI平台中的**可见性**和**引用优先级**，直接影响其在数字时代的竞争力。

**GEO（Generative Engine Optimization，生成式引擎优化）** 是针对AI搜索平台的内容优化策略，通过系统化手段提升品牌在AI回答中的曝光度与正面提及率。本系统是实现GEO策略的**企业级产品平台**，提供从品牌诊断、知识库建设、Prompt管理、内容生产到效果追踪的全链路能力。

### 1.2 产品目标

| 目标维度 | 具体目标 |
|----------|----------|
| **业务目标** | 帮助企业在AI搜索环境中建立品牌认知优势，提升品牌在主流AI平台的可见性和引用率 |
| **产品目标** | 打造国内领先的GEO一站式平台，覆盖诊断→策略→生产→投放→优化的完整闭环 |
| **技术目标** | 构建可扩展的微服务架构，支持多AI平台接入、多模型调用、亿级图谱存储 |

## 3. 详细用例规格说明

### 3.1 UC01 — 品牌AI诊断

| 项目 | 内容 |
|------|------|
| **用例编号** | UC01 |
| **用例名称** | 品牌AI诊断 |
| **参与者** | GEO运营专家（主）、数据分析师（辅） |
| **前置条件** | 用户已登录系统，已配置品牌基础信息 |
| **后置条件** | 系统生成品牌AI诊断报告，数据存入历史记录 |
| **触发条件** | 用户点击"新建诊断"按钮 |
| **优先级** | P0 |

#### 基本事件流

| 步骤 | 参与者动作 | 系统响应 |
|------|-----------|----------|
| 1 | 点击"新建诊断" | — |
| 2 | — | 打开诊断配置页面 |
| 3 | 选择诊断范围（AI平台≥1个、关键词、竞品品牌≤5个） | — |
| 4 | — | 校验配置有效性 |
| 5 | 点击"开始诊断" | — |
| 6 | — | 系统异步执行诊断任务，返回任务ID |
| 7 | — | 采集各AI平台数据（14个主流平台） |
| 8 | — | 执行语义分析和评分计算 |
| 9 | — | 生成品牌影响力报告 |
| 10 | 收到诊断完成通知（消息推送） | — |
| 11 | 查看诊断报告 | — |
| 12 | — | 展示多维度评分和可视化图表 |
| 13 | 导出报告（可选） | — |
| 14 | — | 生成Excel/PDF报告文件 |

#### 备选事件流

| 编号 | 条件 | 处理方式 |
|------|------|----------|
| 3a | 未选择任何AI平台 | 系统提示"请至少选择一个AI平台"，阻止提交 |
| 6a | 诊断任务超时（>30分钟） | 系统标记任务为"超时"，提示用户稍后查看 |
| 7a | 某AI平台API不可用 | 系统跳过该平台，在报告中标记"数据缺失" |
| 11a | 诊断结果异常 | 系统提示"诊断结果异常，建议重新诊断" |

#### 业务规则

1. 诊断任务支持14个主流AI平台（ChatGPT、Perplexity、Claude、Gemini、豆包、Kimi、DeepSeek、文心一言、通义千问、智谱、讯飞星火、腾讯混元、Google AI Overviews等）
2. 诊断报告包含**曝光度**、**语义占位**、**竞争优势**三个维度评分
3. 诊断历史数据保留≥180天
4. 单次诊断最多支持5个竞品对比
5. 诊断任务创建后30分钟内完成（10个平台）

| 编号 | 指标名称 | 要求值 | 说明 |

### 6.2 可用性要求

| 编号 | 指标名称 | 要求值 | 说明 |
|------|----------|--------|------|

| AR-02 | 年非计划停机时间 | ≤8.76小时 | 全年累计非计划停机时间 |

### 6.3 安全要求

#### 6.3.1 数据传输安全

| 编号 | 要求 | 说明 |
|------|------|------|
| SR-01 | TLS 1.2+加密 | 所有客户端与服务器之间的通信必须使用TLS 1.2+加密 |
| SR-02 | AES-256数据加密 | 敏感数据（API密钥、用户凭证等）存储时使用AES-256加密 |
| SR-03 | API传输签名 | 所有API请求需进行HMAC-SHA256签名验证 |

#### 6.3.2 身份认证与访问控制

| 编号 | 要求 | 说明 |
|------|------|------|
| SR-04 | 多因素认证（MFA） | 管理员账户必须启用MFA |
| SR-05 | RBAC+ABAC权限模型 | 采用混合权限模型，支持细粒度权限管理 |
| SR-06 | 密码策略 | 密码≥8位，包含大小写字母、数字和特殊字符，90天强制更换 |
| SR-07 | 会话管理 | 会话超时≤30分钟，同一账户最多3个并发会话 |
| SR-08 | OAuth2.0/API Key认证 | 第三方集成使用OAuth2.0或API Key认证 |

#### 6.3.3 审计与日志

| 编号 | 要求 | 说明 |
|------|------|------|
| SR-09 | 审计日志保留 | 审计日志保留期限≥180天 |
| SR-10 | 日志完整性 | 审计日志采用防篡改机制 |
| SR-11 | 异常行为检测 | 自动检测异常登录、异常操作频率等安全事件 |

### 6.4 兼容性要求

| 浏览器 | 最低版本 | 支持等级 |
|--------|----------|----------|
| Google Chrome | 90+ | A级（完全支持） |
| Mozilla Firefox | 88+ | A级（完全支持） |
| Apple Safari | 14+ | A级（完全支持） |
| Microsoft Edge | 90+ | A级（完全支持） |

| 分辨率 | 要求 |
|--------|------|
| 最低分辨率 | ≥1366×768 |
| 推荐分辨率 | ≥1920×1080 |
| 响应式适配 | 支持1366×768至3840×2160全分辨率范围 |

### 6.5 可扩展性要求

| 编号 | 要求 | 说明 |
|------|------|------|
| SR-01 | 水平扩展 | 应用服务层支持水平扩展（无状态设计） |
| SR-02 | 数据库扩展 | 支持数据库读写分离和分库分表 |
| SR-03 | 插件机制 | AI平台对接、评分模型等核心组件支持插件化扩展 |
| SR-04 | RESTful API | 所有对外接口遵循RESTful设计规范，支持版本化管理 |
| SR-05 | 消息队列 | 核心业务流程采用消息队列异步处理 |
| SR-06 | 配置化 | 业务规则、评分权重、告警阈值等参数支持后台配置化调整 |

### 6.6 合规要求

本系统须符合《信息安全技术 网络安全等级保护基本要求》（GB/T 22239-2019）中**等保三级**的相关要求，关键合规项包括：

| 合规领域 | 关键要求 |
|----------|----------|
| 身份鉴别 | 用户身份唯一标识、MFA、登录失败锁定 |
| 访问控制 | 权限最小化、三权分立、默认拒绝策略 |
| 安全审计 | 审计覆盖关键事件、日志保留≥180天、防篡改 |
| 数据脱敏 | 敏感数据识别、展示脱敏、导出脱敏 |
| 数据传输 | TLS 1.2+加密、HMAC签名、API频率限制 |
