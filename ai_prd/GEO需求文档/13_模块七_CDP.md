# M07 模块七：客户数据平台 CDP（Customer Data Platform）

> **模块定位**：GEO 系统的"数据基座"，负责多源数据接入、统一用户画像和标签管理，为上层营销触达、AI 优化、效果分析提供标准化的客户数据支撑。
>
> **竞品参考**：CDP 产品（Salesforce CDP / Marketing Cloud）
>
> **优先级**：P1
>
> **文档版本**：v1.0
>
> **最后更新**：2026-06-22

---

## 13.1 功能清单

| 编号 | 功能名称 | 优先级 | 说明 |
|------|---------|--------|------|
| M07-F01 | 多源数据接入 | P1 | 支持 MySQL / Hive / ClickHouse / Kafka / API / 文件上传等多源异构数据接入，提供标准化 Connector 框架 |
| M07-F02 | 数据清洗治理 | P1 | 提供 20+ 种清洗算子（去重、格式化、空值填充、异常值过滤、字段映射等），支持可视化配置清洗规则链 |
| M07-F03 | 统一用户身份 | P1 | 构建 One-ID 体系，通过多源 ID 匹配与合并，将分散在不同系统的同一用户统一为唯一身份标识 |
| M07-F04 | 360° 用户画像 | P1 | 基于多源融合数据生成 360 度客户画像，涵盖基础属性、行为特征、偏好标签、消费能力等维度 |
| M07-F05 | 标签创建管理 | P1 | 支持 11 种标签创建方式（规则标签、SQL 标签、行为事件标签、模型标签、时间窗口标签等），提供标签全生命周期管理 |
| M07-F06 | 人群管理 | P1 | 支持人群创建、编辑、扩展、交并差运算，圈选目标群体并推送至下游营销渠道 |
| M07-F07 | 数据资产目录 | P2 | 提供数据血缘追踪、数据地图浏览、元数据管理，帮助用户理解数据来龙去脉 |
| M07-F08 | 数据导出 | P1 | 支持将用户画像、标签数据、人群列表导出为 Excel / CSV 等格式，支持自定义字段选择 |

## 13.3 交互说明

| 场景 | 触发条件 | 交互流程 | 预期结果 |
|------|---------|---------|---------|
| **数据源接入** | 用户点击"新建数据源" | ① 选择数据源类型（MySQL/Hive/ClickHouse/Kafka/API/文件）→ ② 填写连接配置（Host/Port/库名/认证信息）→ ③ 测试连接 → ④ 选择同步表与字段 → ⑤ 配置同步策略（全量/增量/实时）→ ⑥ 确认创建 | 数据源创建成功，自动触发首次数据同步任务，任务状态显示在监控面板 |
| **清洗规则配置** | 用户在数据清洗页面点击"新建规则" | ① 选择目标数据源和表 → ② 拖拽/添加清洗算子（去重→格式化→空值填充→异常过滤→字段映射...）→ ③ 配置算子参数 → ④ 预览清洗效果（显示前后对比样本数据）→ ⑤ 保存规则链 → ⑥ 配置调度周期 | 清洗规则保存成功，按调度周期自动执行，执行日志可查看 |
| **One-ID 管理** | 用户进入 One-ID 管理页面 | ① 查看当前 ID 体系（手机号/邮箱/设备ID/微信OpenID/会员ID 等）→ ② 配置 ID 匹配规则（优先级、权重、冲突策略）→ ③ 查看 ID Mapping 映射表 → ④ 手动合并/拆分身份记录 → ⑤ 查看合并历史 | One-ID 体系运行正常，身份合并/拆分实时生效，映射表可查询 |
| **画像查看** | 用户搜索用户并进入画像详情 | ① 输入用户标识（One-ID/手机号/设备ID）→ ② 展示 360°画像全景（基础属性、行为时间线、标签云、消费能力评分）→ ③ 支持按维度展开/收起 → ④ 支持查看画像更新时间与数据来源 | 完整展示用户画像，数据实时可查，来源可追溯 |
| **标签管理** | 用户创建新标签 | ① 选择标签创建方式（11 种之一）→ ② 配置标签定义（名称/描述/计算规则/更新周期）→ ③ 预览标签覆盖人群规模 → ④ 保存并发布 → ⑤ 标签进入计算队列 | 标签创建成功，按配置周期自动计算，覆盖人群规模实时更新 |
| **人群管理** | 用户创建人群 | ① 选择创建方式（标签组合/行为条件/文件上传/已有群扩展）→ ② 配置圈选条件（拖拽标签+行为事件+时间窗口组合）→ ③ 预览人群规模与画像分布 → ④ 保存人群 → ⑤ 支持推送至下游渠道（广告平台/短信/邮件等） | 人群创建成功，规模实时计算，可一键推送至指定渠道 |

## 13.4 错误处理规范

| 错误场景 | 错误码 | 触发条件 | 处理策略 | 用户提示 |
|---------|--------|---------|---------|---------|
| **数据源接入失败** | CDP-DS-001 | 数据库连接超时 / 认证失败 / 网络不可达 | ① 记录失败日志 → ② 自动重试 3 次（间隔 30s/60s/120s）→ ③ 重试失败后标记数据源状态为"异常"→ ④ 触发告警通知 | "数据源连接失败，已自动重试 3 次。请检查网络或认证配置后手动重试。" |
| **数据源结构变更** | CDP-DS-002 | 源表字段被删除/修改/新增 | ① 自动检测 Schema 变更 → ② 暂停受影响同步任务 → ③ 通知管理员确认变更影响 → ④ 支持一键适配新 Schema | "检测到数据源表结构已变更，同步任务已暂停。请确认变更后重新配置字段映射。" |
| **清洗规则不适配** | CDP-CL-001 | 清洗算子与字段类型不匹配 / 规则链存在逻辑冲突 | ① 规则保存时自动校验算子与字段类型兼容性 → ② 不兼容时阻止保存并高亮错误节点 → ③ 提供修复建议 | "清洗规则配置有误：[算子名称] 不支持 [字段类型] 类型字段。请调整算子或更换字段。" |
| **清洗执行异常** | CDP-CL-002 | 清洗过程中数据量超出阈值 / 内存溢出 | ① 自动终止异常任务 → ② 保留已处理数据快照 → ③ 记录异常日志 → ④ 建议用户缩小批次或优化规则 | "清洗任务执行异常，已自动终止。建议缩小数据批次或优化清洗规则后重试。" |
| **ID Mapping 冲突** | CDP-ID-001 | 同一用户被多个 ID 匹配到不同身份 / 匹配置信度低于阈值 | ① 标记冲突记录 → ② 按预设策略自动处理（高置信度优先 / 最近活跃优先）→ ③ 无法自动处理的转入人工审核队列 → ④ 用户可在 One-ID 页面手动合并/拆分 | "检测到 [N] 条身份冲突记录，已自动处理 [M] 条，[K] 条需人工确认。请前往 One-ID 管理页面处理。" |
| **画像计算失败** | CDP-PF-001 | 画像更新时源数据缺失 / 计算引擎异常 | ① 使用最近一次有效画像快照兜底 → ② 记录失败原因 → ③ 触发重试 → ④ 超过重试上限后标记画像为"待更新" | "用户画像更新失败，当前展示为最近一次有效数据。系统将自动重试更新。" |
| **标签计算超时** | CDP-TG-001 | 标签计算任务超过预设时间阈值 | ① 自动终止超时任务 → ② 记录超时日志 → ③ 建议用户缩小计算范围或优化计算规则 → ④ 支持手动重新触发 | "标签计算任务超时，已自动终止。建议缩小时间窗口或优化计算规则后重试。" |
| **人群规模超限** | CDP-SG-001 | 人群圈选结果超过系统预设上限（如 5000 万） | ① 阻止人群创建 → ② 提示用户缩小圈选范围 → ③ 建议增加筛选条件或拆分为多个人群 | "人群规模超出系统上限（5000万），请增加筛选条件缩小范围后重试。" |
| **数据导出失败** | CDP-EX-001 | 导出数据量过大 / 文件生成超时 / 存储空间不足 | ① 导出前预检查数据量 → ② 超过阈值时提示用户分批导出或缩小范围 → ③ 支持异步导出（完成后通知下载）→ ④ 记录导出失败日志 | "导出数据量过大，已转为异步导出。完成后将通知您下载，请留意通知。" |
| **导出文件过期** | CDP-EX-002 | 导出文件保留超过 72 小时 | ① 自动清理过期导出文件 → ② 用户再次下载时提示"文件已过期，请重新导出" | "导出文件已过期（超过72小时），请重新发起导出。" |

**Connector 框架设计要点**：

- **统一接口**：所有 Connector 实现 `DataSourceConnector` 接口，包含 `connect()`、`fetchSchema()`、`fetchData()`、`syncIncremental()`、`close()` 五个核心方法
- **插件化架构**：新增数据源类型只需实现对应 Connector 并注册到 Connector Registry，无需修改核心框架
- **同步模式**：支持全量同步（每日/每周）、增量同步（基于时间戳/自增ID/CDC Binlog）、实时同步（Kafka 流式消费）
- **连接池管理**：内置连接池，支持连接复用、超时控制、自动重连
- **数据分区**：大数据量自动分片并行拉取，单分片默认 10 万条，可配置

```
│  │              清洗算子库（20+）                    │  │
│  │                                                │  │

│  │  └────────┘ └────────┘ └────────┘ └────────┘  │  │
│  │  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐  │  │
│  │  │类型转换 │ │异常过滤 │ │ 截断   │ │ 拆分   │  │  │
│  │  └────────┘ └────────┘ └────────┘ └────────┘  │  │
│  │                                                │  │
│  │  高级算子：                                      │  │
│  │  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐  │  │

│  └──────────┘  └──────────┘  └──────────┘           │
└──────────────────────────────────────────────────────┘
```

**清洗引擎设计要点**：

- **DAG 编排**：清洗规则以 DAG（有向无环图）形式编排，支持算子间的依赖关系与并行执行
- **算子注册**：所有算子注册到算子引擎，支持自定义算子扩展（实现 `CleanOperator` 接口）
- **执行引擎**：批量清洗基于 Apache Spark，流式清洗基于 Apache Flink，交互式预览基于内存计算
- **质量报告**：每次清洗执行后生成质量报告，包含处理量、清洗率、异常率、耗时等指标

### 13.5.3 ID Mapping 算法

```
┌──────────────────────────────────────────────────────┐
│                One-ID 身份解析引擎                      │
│                                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │           ID 类型定义                           │  │
│  │                                                │  │
│  │  确定性 ID：手机号、邮箱、身份证号、会员卡号        │  │
│  │  概率性 ID：设备ID、IP地址、浏览器指纹             │  │
│  │  社交ID：微信OpenID、支付宝ID、抖音ID            │  │
│  └────────────────────────────────────────────────┘  │
│                          ↓                           │
│  ┌────────────────────────────────────────────────┐  │
│  │           匹配流程                               │  │
│  │                                                │  │
│  │  Step 1: 确定性匹配（精确匹配）                   │  │
│  │    手机号 A == 手机号 B → 直接合并               │  │
│  │                                                │  │
│  │  Step 2: 概率性匹配（模糊匹配）                   │  │
│  │    设备ID + IP + 行为模式 → 计算相似度得分        │  │
│  │    相似度 ≥ 阈值(0.85) → 自动合并               │  │
│  │    相似度 ∈ [0.6, 0.85) → 人工审核              │  │
│  │                                                │  │
│  │  Step 3: 图连通性分析                            │  │
│  │    构建 ID 关系图 → 连通分量分析 → 身份簇合并     │  │
│  └────────────────────────────────────────────────┘  │
│                          ↓                           │
│  ┌────────────────────────────────────────────────┐  │
│  │           冲突解决策略                           │  │
│  │                                                │  │
│  │  · 高置信度优先：确定性匹配 > 概率性匹配          │  │
│  │  · 最近活跃优先：最近活跃的身份属性优先保留        │  │
│  │  · 数据源优先级：配置数据源权重，高权重优先        │  │
│  │  · 人工审核：无法自动解决的冲突进入审核队列        │  │
│  └────────────────────────────────────────────────┘  │
│                          ↓                           │
│  ┌────────────────────────────────────────────────┐  │
│  │            输出：One-ID 映射表                    │  │
│  │                                                │  │
│  │  One-ID  |  手机号  |  设备ID  |  邮箱  | ...   │  │
│  │  O_001   | 138xxx   | dev_001 | a@b.c | ...   │  │
│  │  O_002   | 139xxx   | dev_002 | c@d.e | ...   │  │
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

**ID Mapping 设计要点**：

- **图存储**：ID 关系图使用图数据库（Neo4j / JanusGraph）存储，支持高效连通性查询
- **匹配算法**：确定性匹配使用哈希精确查找；概率性匹配使用 Jaccard 相似度 + 行为特征向量余弦相似度
- **增量更新**：新数据接入时仅对增量部分执行匹配，不影响已有映射关系
- **版本管理**：每次合并/拆分操作记录版本快照，支持回滚
