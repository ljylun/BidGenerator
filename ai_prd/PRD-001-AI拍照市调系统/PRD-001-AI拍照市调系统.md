## 1. 产品概述

### 1.1 背景与问题

| 维度 | 现状 |
|------|------|
| **痛点来源** | 单品运营部 |
| **当前方式** | 市调人员每日人工拍摄竞争对手（如百果园）价签/陈列，手写记录 |
| **核心问题** | 数据非结构化、历史决策逻辑无法复盘、信息全在"脑子里"或旧手机里 |
| **影响范围** | 采购缺乏竞品价格历史趋势分析，定价决策依赖经验 |
| **量化损失** | 每周 2 人天 × 52 周 = 104 人天/年用于低效市调；定价偏差导致毛利率损失约 1-2% |

### 1.2 产品定义

**一句话描述**：通过 OCR + 多模态大模型，市调人员拍照即可自动提取竞品商品名称、规格、价格并结构化存储至钉钉AI表格，自动生成比价报告，建立实时"竞品价格雷达"。

**产品愿景**：构建零售行业首个 AI 驱动的竞品情报平台，从"经验定价"升级为"数据定价"。

**产品载体**：本产品为运行在钉钉平台上的**钉钉AI表格应用**，利用钉钉AI表格的多维表格能力、自动化流程、AI字段识别、权限管理等原生功能，实现市调数据的采集、存储、分析与协作。

### 1.3 目标用户

| 角色 | 用户画像 | 使用场景 | 核心诉求 | 使用频率 |
|------|----------|----------|----------|----------|
| 市调人员 | 25-35岁，一线执行，手机操作为主 | 每日外出市调，需要快速采集 | 快速采集、减少手工录入 | 每日 2-4 小时 |
| 单品运营 | 28-40岁，数据分析能力强 | 日常比价分析、定价建议 | 实时竞品价格数据、趋势图 | 每日查看 |
| 采购人员 | 30-45岁，关注成本和竞争 | 采购决策、定价策略 | 历史价格趋势、比价报告 | 每周查看 |
| 管理层 | 40+岁，关注全局 | 经营决策、战略调整 | 竞品动态概览 | 每月查看 |

### 1.4 产品边界

**包含功能**：
- 拍照采集竞品价签和陈列
- OCR 自动识别并结构化存储
- 人工复核工作台
- 比价报告生成和推送
- 价格趋势分析
- 异常价格告警

**不包含功能**：
- 竞品库存分析（后续规划）
- 竞品促销策略分析（后续规划）
- 竞品供应链分析（不在范围内）

## 4. 技术方案

### 4.1 模型选择

| 项目 | 方案 |
|------|------|
| **推荐模型** | qwen3-vl-flash |
| **调用方式** | Batch 批量调用（非实时） |
| **输入单价** | 0.000075 元/千 Token（32K 以内） |
| **输出单价** | 0.00075 元/千 Token（32K 以内） |
| **免费额度** | 各 100 万 Token，有效期 90 天 |

**选择理由**：相比 OCR 专用模型（qwen-vl-ocr），vl-flash 对商品陈列整体理解更全面；Batch 调用享受半价优惠，适合批量处理。

### 4.6 关键技术实现

| 技术点 | 实现方案 |
|--------|----------|
| 价签裁剪 | 前端 OpenCV.js 自动识别价签区域并裁剪 |
| 批量处理 | 延迟队列累积至 100 张触发一次 Batch API 调用 |
| 结果缓存 | Redis 缓存 30 天，重复查询直接返回，减少 30% 调用量 |
| 人工复核 | 置信度 < 85% 自动标记，推送至AI表格复核视图 |
| 离线支持 | 钉钉AI表格本地缓存机制，联网后自动同步 |
| 图片压缩 | 前端压缩至 1024px 以内，控制上传大小 ≤ 500KB |
| 去重机制 | 基于图片相似度（pHash）去重，避免重复识别 |
| 钉钉集成 | 通过钉钉开放平台API实现数据读写和消息推送 |
