## 1. 产品概述

### 1.1 背景与问题

| 维度 | 现状 |
|------|------|
| **痛点来源** | 客服部、运营部 |
| **当前方式** | 客服人员手动记录客诉、手动分类、手动分派处理人 |
| **核心问题** | 分类标准不统一、响应慢、处理进度难追踪、无法量化分析 |
| **业务影响** | 客诉处理时效差，客户满意度低；管理层无法及时发现系统性问题 |
| **量化损失** | 平均处理时效 48 小时（行业优秀值 12 小时）；重复客诉占比 30% |

### 1.2 产品定义

**一句话描述**：AI 自动识别客诉内容、智能分类（商品质量/服务态度/配送问题等）、自动分派处理人、追踪处理进度，实现客诉全生命周期自动化管理。

**产品愿景**：构建智能化客诉管理系统，将客诉处理时效从 48 小时缩短至 12 小时，客户满意度提升至 90%+。

**产品载体**：本产品为运行在钉钉平台上的**钉钉AI表格应用**，利用钉钉AI表格的多维表格能力、自动化流程、AI字段识别、权限管理等原生功能，实现客诉工单的全流程自动化管理。

### 1.3 目标用户

| 角色 | 用户画像 | 使用场景 | 核心诉求 | 使用频率 |
|------|----------|----------|----------|----------|
| 客服人员 | 22-35 岁，一线服务 | 客诉受理 | 快速记录、自动分类 | 每日 |
| 店长 | 30-45 岁，门店管理 | 处理门店客诉 | 及时处理、进度可视 | 每日 |
| 品控人员 | 28-40 岁，质量管控 | 分析质量问题 | 问题分类统计 | 每周 |
| 运营管理层 | 35-50 岁，全局管理 | 客诉趋势分析 | 系统性问题发现 | 每周 |

## 2. 业务流程

### 2.1 客诉处理主流程

```
客户通过多渠道提交客诉
（电话/在线/微信/门店）
        │
        ▼
AI 自动识别与分类
  ├─ 提取关键信息（商品、问题类型、严重程度）
  ├─ 自动分类（商品质量/服务态度/配送/其他）
  └─ 自动分派处理人
        │
        ▼
工单创建（钉钉AI表格）
  ├─ 生成工单编号
  ├─ 记录客户信息
  └─ 设置处理时限
        │
        ▼
处理人接收通知
  ├─ 查看工单详情
  ├─ 处理并记录处理过程
  └─ 提交处理结果
        │
        ▼
客户反馈
  ├─ 满意 → 工单关闭
  └─ 不满意 → 升级处理
        │
        ▼
工单归档 → 数据分析
```

#### 核心表结构（备用关系型数据库方案）

```sql
-- 客诉工单表
CREATE TABLE complaint_ticket (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    ticket_no       VARCHAR(50) UNIQUE NOT NULL COMMENT '工单编号',
    customer_name   VARCHAR(100) COMMENT '客户名称',
    customer_phone  VARCHAR(20) COMMENT '客户电话',
    store_id        BIGINT COMMENT '关联门店ID',
    content         TEXT NOT NULL COMMENT '客诉内容',
    category1       VARCHAR(50) COMMENT '一级分类',
    category2       VARCHAR(50) COMMENT '二级分类',
    severity        VARCHAR(10) COMMENT 'P1/P2/P3',
    status          VARCHAR(20) DEFAULT 'OPEN' COMMENT 'OPEN/PROCESSING/RESOLVED/CLOSED',
    assignee        VARCHAR(50) COMMENT '处理人',
    sla_deadline    DATETIME COMMENT '处理时限',
    resolution      TEXT COMMENT '处理结果',
    satisfaction    VARCHAR(20) COMMENT 'SATISFIED/NEUTRAL/UNSATISFIED',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    processed_at    DATETIME COMMENT '处理时间',
    closed_at       DATETIME COMMENT '关闭时间',
    INDEX idx_status (status),
    INDEX idx_category (category1, category2),
    INDEX idx_assignee (assignee)
);

-- 分类规则表
CREATE TABLE classification_rule (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    rule_name       VARCHAR(200) NOT NULL COMMENT '规则名称',
    keywords        JSON COMMENT '触发关键词',
    category1       VARCHAR(50) COMMENT '一级分类',
    category2       VARCHAR(50) COMMENT '二级分类',
    severity        VARCHAR(10) COMMENT 'P1/P2/P3',
    priority        INT DEFAULT 0 COMMENT '优先级',
    status          TINYINT DEFAULT 1,
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 处理人配置表
CREATE TABLE assignee_config (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         VARCHAR(50) NOT NULL COMMENT '处理人ID',
    role            VARCHAR(50) COMMENT '角色',
    categories      JSON COMMENT '负责分类',
    max_tickets     INT DEFAULT 10 COMMENT '最大工单数',
    status          TINYINT DEFAULT 1,
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 4.4 钉钉AI表格集成方案

#### 4.4.1 钉钉AI表格应用架构

本产品作为钉钉AI表格应用运行，利用钉钉开放平台提供的以下核心能力：

| 能力模块 | 用途 | 实现方式 |
|----------|------|----------|
| 多维表格 | 数据存储与管理 | 使用钉钉AI表格作为主数据存储 |
| 自动化流程 | 业务逻辑触发 | 配置自动化规则，实现工单分派和升级 |
| AI字段 | 智能分类 | 利用AI字段能力进行客诉分类 |
| 权限管理 | 数据访问控制 | 配置表格级、行级、列级权限 |
| 消息通知 | 推送提醒 | 通过钉钉机器人推送工单通知 |
| 连接器 | 外部系统集成 | 通过连接器调用外部AI服务 |

#### 4.4.2 钉钉开放平台集成

**钉钉应用配置**：
- 应用类型：企业内部应用
- 运行平台：钉钉AI表格
- 权限范围：
  - `dingtalk:app:table:read` - 表格读取
  - `dingtalk:app:table:write` - 表格写入
  - `dingtalk:user:readonly` - 用户基本信息读取
  - `dingtalk:message:send_as_bot` - 消息发送

#### 4.4.3 前端技术适配

**运行环境要求**：
- 运行平台：钉钉客户端（iOS/Android）内置浏览器
- 技术框架：钉钉AI表格小程序框架（基于钉钉小程序技术栈）
- 兼容性要求：
  - iOS 13.0+
  - Android 8.0+
  - 钉钉客户端版本 6.5.0+
