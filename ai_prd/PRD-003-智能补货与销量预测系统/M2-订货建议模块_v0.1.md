## 1. 模块概述

### 1.1 定位

订货建议模块基于销量预测结果，结合当前库存、在途库存、安全库存等数据，自动生成建议订货量，支持店长审核、调整和确认，最终驱动采购流程。

### 1.2 目标

| 指标 | 目标值 |
|------|--------|
| 订货建议采纳率 | ≥ 70% |
| 缺货率降低 | 从 15% 降至 5%（降低 67%） |
| 推送时效 | 每日 7:00 前推送至店长钉钉 |
| 建议包含理由 | 100% 附带计算逻辑说明 |

### 1.3 用户角色

| 角色 | 使用场景 | 核心诉求 |
|------|----------|----------|
| 店长 | 每日订货决策 | 科学的订货建议，可调整 |
| 采购人员 | 采购订单生成 | 确认后自动生成采购订单 |

## 2. 功能需求

### 2.1 功能清单

| 功能ID | 功能名称 | 优先级 | 描述 |
|--------|----------|--------|------|
| F-002 | 订货建议 | P0 | 自动生成建议订货量 |

### 2.2 用户故事

| 故事ID | 用户故事 | 验收标准 | 优先级 |
|--------|----------|----------|--------|
| US-005 | 作为店长，我希望收到智能订货建议，包含建议数量和理由 | 建议包含计算逻辑说明 | P0 |
| US-006 | 作为店长，我希望可以调整建议数量并说明原因 | 支持手动调整 + 原因记录 | P0 |
| US-007 | 作为系统，我希望当预测库存低于安全库存时自动告警 | 告警延迟 ≤ 1 小时 | P0 |

### 2.3 订货建议计算逻辑

**建议订货量公式**：
```
建议订货量 = 预测销量 + 安全库存 - 当前库存 - 在途库存
```

**约束条件**：
- 考虑供应商最小起订量（MOQ）
- 考虑货架容量上限
- 若计算结果 ≤ 0，建议量为 0（无需补货）

## 3. 数据模型

### 3.1 订货建议表（钉钉AI表格）

| 字段名 | 字段类型 | 说明 |
|--------|----------|------|
| 门店 | 关联 | 关联门店表 |
| 商品 | 关联 | 关联商品表 |
| 建议日期 | 日期 | 建议日期 |
| 预测销量 | 数字 | 预测值 |
| 当前库存 | 数字 | 当前库存量 |
| 在途库存 | 数字 | 在途量 |
| 安全库存 | 数字 | 安全库存量 |
| 建议订货量 | 数字 | 计算值 |
| 最小起订量 | 数字 | 供应商限制 |
| 建议理由 | 文本 | 计算逻辑说明 |
| 状态 | 单选 | 待确认/已接受/已拒绝/已修改 |
| 店长调整后数量 | 数字 | 手动调整值 |
| 店长调整原因 | 文本 | 调整说明 |
| 确认时间 | 日期时间 | 手动记录 |
| 创建时间 | 系统字段 | 自动记录 |

### 3.2 核心表结构（关系型数据库方案）

```sql
CREATE TABLE order_suggestion (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    store_id        BIGINT NOT NULL COMMENT '门店ID',
    product_id      BIGINT NOT NULL COMMENT '商品ID',
    suggest_date    DATE NOT NULL COMMENT '建议日期',
    forecast_qty    DECIMAL(10, 2) COMMENT '预测销量',
    current_stock   DECIMAL(10, 2) COMMENT '当前库存',
    in_transit_qty  DECIMAL(10, 2) COMMENT '在途库存',
    safety_stock    DECIMAL(10, 2) COMMENT '安全库存',
    suggest_qty     DECIMAL(10, 2) NOT NULL COMMENT '建议订货量',
    min_order_qty   DECIMAL(10, 2) COMMENT '最小起订量',
    reason          TEXT COMMENT '建议理由',
    status          VARCHAR(20) DEFAULT 'PENDING' COMMENT 'PENDING/ACCEPTED/REJECTED/MODIFIED',
    manager_qty     DECIMAL(10, 2) COMMENT '店长调整后数量',
    manager_reason  TEXT COMMENT '店长调整原因',
    confirmed_at    DATETIME COMMENT '确认时间',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 4. API 规格

### 4.1 订货建议查询 API

```
GET /api/v1/order/suggestion
请求参数：
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| store_id | Long | 是 | 门店ID |
| date | Date | 是 | 建议日期 |

响应：
{
  "code": 200,
  "data": {
    "store_id": 100,
    "suggest_date": "2026-06-13",
    "suggestions": [
      {
        "product_id": 2001,
        "product_name": "红颜草莓 300g/盒",
        "forecast_qty": 45.0,
        "current_stock": 10.0,
        "in_transit_qty": 20.0,
        "safety_stock": 15.0,

```

```
    "status": "MODIFIED",
    "message": "已更新订货建议"
  }
}
```

## 5. 业务流程

```
每日凌晨 2:00 预测任务完成
         │
         ▼
读取预测结果 + 库存数据
         │
         ▼
计算建议订货量
  ├─ 建议量 = 预测销量 + 安全库存 - 当前库存 - 在途库存
  ├─ 校验最小起订量
  └─ 校验货架容量上限
         │
         ▼
生成建议理由（自然语言）
         │
         ▼
写入钉钉AI表格
         │
         ▼
推送至店长钉钉（每日 7:00 前）
         │
         ▼
店长审核 → 确认/调整/拒绝
         │
         ▼
确认后自动生成采购订单
```
