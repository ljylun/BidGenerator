## 1. 产品概述

### 1.1 背景与问题

| 维度 | 现状 |
|------|------|
| **痛点来源** | 内控/财务、线上运营、数据部 |
| **当前方式** | 水果自然损耗按固定 3% 估算（手工 Excel）；订货靠经验，线上/线下库存不通 |
| **核心问题** | 毛利不准、订货过多（报损）或过少（退单）、历史数据查询受限 |
| **业务影响** | 线上 80% 退单因缺货；损耗核算偏差导致财务数据失真 |
| **量化损失** | 每月报损率约 8%（行业优秀值 3-4%）；缺货率约 15%（行业优秀值 5%） |

### 1.2 产品定义

**一句话描述**：基于历史销量、天气、节假日、促销活动等多维因子，利用时序预测模型预测单店单品未来 3-7 天销量；同时建立动态自然损耗模型，实现"真实毛利"的自动化核算。

**产品愿景**：从"经验订货"升级为"数据驱动的智能补货"，将缺货率降至 5% 以下，报损率降至 4% 以下。

**产品载体**：本产品为运行在钉钉平台上的**钉钉AI表格应用**，利用钉钉AI表格的多维表格能力、自动化流程、AI字段识别、权限管理等原生功能，实现补货预测数据的采集、存储、分析与协作。

### 1.3 目标用户

| 角色 | 用户画像 | 使用场景 | 核心诉求 | 使用频率 |
|------|----------|----------|----------|----------|
| 店长 | 30-45 岁，门店管理者 | 每日订货决策 | 科学的订货建议 | 每日 |
| 采购人员 | 28-40 岁，供应链管理 | 批量采购计划 | 基于预测的采购量建议 | 每周 |
| 内控/财务 | 30-45 岁，财务分析 | 损耗核算 | 真实、动态的损耗数据 | 每月 |
| 运营管理层 | 40+ 岁，关注全局 | 库存健康度 | 全局库存周转率看板 | 每周 |

### 2.3 损耗模型详细定义

**损耗率计算公式**：
```
日损耗率 = 基础损耗率 × K_temp × K_time × K_category

其中：
- 基础损耗率：品类固有属性（如草莓 5%，苹果 1%）
- K_temp = 1 + 0.03 × (实际气温 - 20) / 10
  （气温每升高 10°C，损耗率增加 3%）
- K_time = 1 + 0.05 × (存放时长 - 24) / 24
  （存放每增加 24 小时，损耗率增加 5%）
- K_category：品类修正系数
```

**品类损耗参数表**：

| 品类 | 基础损耗率 | 温度敏感度 | 时间敏感度 | 存储条件 |
|------|-----------|-----------|-----------|----------|
| 草莓 | 5.0% | 高 | 高 | 冷藏 2-4°C |
| 蓝莓 | 4.5% | 高 | 高 | 冷藏 2-4°C |
| 车厘子 | 3.0% | 中 | 高 | 冷藏 2-4°C |
| 西瓜 | 1.5% | 中 | 低 | 常温 |
| 苹果 | 1.0% | 低 | 低 | 冷藏 0-4°C |
| 香蕉 | 3.0% | 高 | 中 | 常温 13-15°C |
| 芒果 | 2.5% | 中 | 中 | 常温 |

## 4. 技术方案

### 4.1 模型选择

| 组件 | 技术方案 | 说明 |
|------|----------|------|
| **销量预测** | Prophet（基线）+ LSTM（进阶） | Prophet 适合有季节性数据，LSTM 适合复杂非线性 |
| **损耗模型** | 多元线性回归 + 规则引擎 | 初期规则引擎，积累数据后引入 ML |
| **数据存储** | 钉钉AI表格 + 时序数据库（TDengine） | 钉钉AI表格存业务数据，TDengine 存时序数据 |
| **缓存** | Redis | 预测结果缓存 |
| **调度** | XXL-Job | 定时任务调度 |
| **消息队列** | RocketMQ | 异步任务处理 |

```sql
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    store_id        BIGINT NOT NULL COMMENT '门店ID',
    product_id      BIGINT NOT NULL COMMENT '商品ID',
    suggest_date    DATE NOT NULL COMMENT '建议日期',
    forecast_qty    DECIMAL(10, 2) COMMENT '预测销量',
    current_stock   DECIMAL(10, 2) COMMENT '当前库存',
    in_transit_qty  DECIMAL(10, 2) COMMENT '在途库存',
    safety_stock    DECIMAL(10, 2) COMMENT '安全库存',
    suggest_qty     DECIMAL(10, 2) NOT NULL COMMENT '建议订货量',
    min_order_qty   DECIMAL(10, 2) COMMENT '最小起订量',
    reason          TEXT COMMENT '建议理由',
    status          VARCHAR(20) DEFAULT 'PENDING' COMMENT 'PENDING/ACCEPTED/REJECTED/MODIFIED',
    manager_qty     DECIMAL(10, 2) COMMENT '店长调整后数量',
    manager_reason  TEXT COMMENT '店长调整原因',
    confirmed_at    DATETIME COMMENT '确认时间',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 动态损耗记录表
CREATE TABLE dynamic_loss (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    store_id        BIGINT NOT NULL COMMENT '门店ID',
    product_id      BIGINT NOT NULL COMMENT '商品ID',
    loss_date       DATE NOT NULL COMMENT '损耗日期',
    temperature     DECIMAL(5, 2) COMMENT '当日气温',
    storage_hours   INT COMMENT '存储时长（小时）',
    base_loss_rate  DECIMAL(5, 4) COMMENT '基础损耗率',
    temp_coefficient DECIMAL(5, 4) COMMENT '温度系数',
    time_coefficient DECIMAL(5, 4) COMMENT '时间系数',
    category_coefficient DECIMAL(5, 4) COMMENT '品类系数',
    dynamic_loss_rate DECIMAL(5, 4) COMMENT '动态损耗率',
    loss_amount     DECIMAL(10, 2) COMMENT '损耗金额',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_store_product_date (store_id, product_id, loss_date)
);

-- 品类损耗参数表
CREATE TABLE category_loss_config (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    category_id     BIGINT NOT NULL COMMENT '品类ID',
    category_name   VARCHAR(100) COMMENT '品类名称',
    base_loss_rate  DECIMAL(5, 4) NOT NULL COMMENT '基础损耗率',
    temp_sensitivity VARCHAR(20) COMMENT '温度敏感度：HIGH/MEDIUM/LOW',
    time_sensitivity VARCHAR(20) COMMENT '时间敏感度：HIGH/MEDIUM/LOW',
    storage_condition VARCHAR(50) COMMENT '存储条件',
    optimal_temp_min DECIMAL(5, 2) COMMENT '最适温度下限',
    optimal_temp_max DECIMAL(5, 2) COMMENT '最适温度上限',
    status          TINYINT DEFAULT 1,
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 预测准确率统计表
CREATE TABLE forecast_accuracy (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    stat_date       DATE NOT NULL COMMENT '统计日期',
    store_id        BIGINT COMMENT '门店ID（NULL表示全国）',
    category_id     BIGINT COMMENT '品类ID（NULL表示全部）',
    total_forecasts INT COMMENT '预测总数',
    mape            DECIMAL(5, 4) COMMENT '平均绝对百分比误差',
    rmse            DECIMAL(10, 4) COMMENT '均方根误差',
    accuracy_rate   DECIMAL(5, 4) COMMENT '准确率（1-MAPE）',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_date_store_category (stat_date, store_id, category_id)
);
```

### 4.5 模型评估指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| MAPE | 平均绝对百分比误差 | ≤ 25%（加权平均） |
| RMSE | 均方根误差 | 品类差异化 |
| 偏差率 | 预测值与实际值的系统性偏差 | ≤ 5% |
| 覆盖率 | 可预测 SKU 占总 SKU 比例 | ≥ 80% |

### 4.6 钉钉AI表格集成方案

#### 4.6.1 钉钉AI表格应用架构

本产品作为钉钉AI表格应用运行，利用钉钉开放平台提供的以下核心能力：

| 能力模块 | 用途 | 实现方式 |
|----------|------|----------|
| 多维表格 | 数据存储与管理 | 使用钉钉AI表格作为主数据存储 |
| 自动化流程 | 业务逻辑触发 | 配置自动化规则，实现预测任务调度 |
| AI字段 | 智能计算 | 利用AI字段能力进行预测计算 |
| 权限管理 | 数据访问控制 | 配置表格级、行级、列级权限 |
| 消息通知 | 推送提醒 | 通过钉钉机器人推送订货建议 |
| 连接器 | 外部系统集成 | 通过连接器调用外部AI服务 |

#### 4.6.2 钉钉开放平台集成

**钉钉应用配置**：
- 应用类型：企业内部应用
- 运行平台：钉钉AI表格
- 权限范围：
  - `dingtalk:app:table:read` - 表格读取
  - `dingtalk:app:table:write` - 表格写入
  - `dingtalk:user:readonly` - 用户基本信息读取
  - `dingtalk:message:send_as_bot` - 消息发送

#### 4.6.3 前端技术适配

**运行环境要求**：
- 运行平台：钉钉客户端（iOS/Android）内置浏览器
- 技术框架：钉钉AI表格小程序框架（基于钉钉小程序技术栈）
- 兼容性要求：
  - iOS 13.0+
  - Android 8.0+
  - 钉钉客户端版本 6.5.0+
