## 一、功能角色矩阵说明

### 1.1 功能描述

- **功能名称：** 整改工单管理
- **所属模块：** AI视觉督导系统
- **功能描述：** 对AI审核不合格的照片自动生成整改工单，推送至店长钉钉，店长上传整改照片后系统自动比对验证，实现整改闭环管理。

### 1.2 角色权限总览

| 角色      | 功能权限                        | 数据权限   |
| ------- | --------------------------- | ------ |
| 店长 | 查看工单、上传整改照片、查看验证结果         | 仅本店工单 |
| 督导人员 | 查看工单、指派工单、验证整改、关闭工单        | 全量数据 |
| 运营管理层 | 查看工单、查看整改进度看板、导出数据         | 全量数据 |

### 1.3 功能角色矩阵

| 功能点  | 店长 | 督导人员 | 运营管理层 |
| ---- | :-----: | :-----: | :-----: |
| 查看工单 |    是    |    是    |    是    |
| 上传整改照片 |    是    |    否    |    否    |
| 指派工单 |    否    |    是    |    否    |
| 验证整改 |    否    |    是    |    否    |
| 关闭工单 |    否    |    是    |    否    |
| 导出数据 |    否    |    否    |    是    |

## 三、状态流转与流程图

### 3.1 整改工单主流程

```mermaid
flowchart TD
    A[AI审核不合格] --> B[自动生成整改工单]
    B --> C[推送整改通知至店长钉钉]
    C --> D[店长查看工单详情]
    D --> E[店长整改后上传整改照片]
    E --> F[系统自动比对整改前后照片]
    F --> G{验证结果}
    G -->|合格| H[工单状态变更为已验证]
    G -->|不合格| I[打回重新整改]
    H --> J[督导确认关闭工单]
    I --> E
    J --> K[工单关闭，更新合规率]
```

### 3.2 工单状态流转图

```mermaid
stateDiagram-v2
    [*] --> 待处理: AI审核不合格自动生成
    待处理 --> 整改中: 店长开始整改
    整改中 --> 待验证: 店长上传整改照片
    待验证 --> 已验证: AI自动比对通过
    待验证 --> 整改中: AI比对不通过，打回
    已验证 --> 已关闭: 督导确认关闭
```

## 八、特殊说明

### 8.1 工单生成规则

- AI审核不合格时自动生成整改工单，无需人工干预
- 同一张照片的多个问题合并为一个工单
- 工单编号格式：R + 日期(8位) + 序号(4位)

### 8.2 整改照片比对逻辑

- 使用特征向量比对技术，计算整改前后照片的相似度
- 相似度 ≥ 85% 判定为整改合格
- 比对不通过的工单自动打回，店长收到重新整改通知

### 8.3 其他特殊规则

1. 工单状态流转严格按照"待处理→整改中→待验证→已验证→已关闭"顺序，不可跳跃
2. 已关闭的工单不可再次修改
3. 店长上传整改照片后，系统自动触发AI验证，无需人工触发
