## 1. 产品概述

### 1.1 背景与问题

| 维度 | 现状 |
|------|------|
| **痛点来源** | 督导部、工程/弱电、线上运营 |
| **当前方式** | 每周五至周日人工审核 300 家门店上传的约 1,000 张陈列照片，肉眼判断 |
| **核心问题** | 效率极低（72 小时出结果）、主观偏差大、无法实时发现问题 |
| **业务影响** | 80% 线上退单因"缺货"导致（系统显示有货实际无货），陈列空置造成销售损失 |
| **量化损失** | 每周 3 名督导 × 3 天 = 9 人天用于低效审核；陈列合规率仅约 60% |

### 1.2 产品定义

**一句话描述**：利用计算机视觉（CV）+ 多模态大模型，自动审核门店陈列照片（商品摆放、价签合规、堆头饱满度），实时发现货架缺货、员工违规等行为，实现从"人眼巡检"到"AI 实时督导"的升级。

**产品愿景**：建立行业首个 AI 驱动的门店合规管理体系，将陈列合规率从 60% 提升至 90%+。

**产品载体**：本产品为运行在钉钉平台上的**钉钉AI表格应用**，利用钉钉AI表格的多维表格能力、自动化流程、AI字段识别、权限管理等原生功能，实现督导数据的采集、存储、分析与协作。

### 1.3 目标用户

| 角色 | 用户画像 | 使用场景 | 核心诉求 | 使用频率 |
|------|----------|----------|----------|----------|
| 督导人员 | 28-40 岁，巡店频繁 | 每周审核门店陈列 | 减少人工审核量，提高准确性 | 每周 3 天 |
| 店长 | 30-45 岁，门店管理者 | 接收整改通知 | 及时了解问题，快速整改 | 每日 |
| 商学院 | 培训管理人员 | 陈列标准培训 | 建立量化评估体系 | 每月 |
| 运营管理层 | 区域/全国负责人 | 合规率统计 | 全局陈列合规率看板 | 每周 |
| 工程/弱电 | 技术人员 | 设备监控 | 实时发现货架缺货 | 实时 |

### 1.4 产品边界

**包含功能**：
- 门店陈列照片自动审核（商品摆放、价签、堆头）
- 价签合规检测（有无、对应、价格）
- 禁售商品检测
- 整改工单生成与闭环追踪
- 合规率统计看板
- 货架缺货预警（基于现有摄像头）

**不包含功能**：
- 门店装修改造建议（不在范围内）
- 员工行为全面监控（仅限抽烟、缺岗等明确违规）
- 供应链补货（关联但不包含在本系统）

### 2.2 货架缺货预警流程

```
门店 400W 像素摄像头 → 边缘计算盒子
        │
        ▼
实时视频流分析（每 5 分钟截取一帧）
        │
        ▼
货架空置率检测
  ├─ 爆品区空置率 > 30% → 立即推送店长补货
  ├─ 常规区空置率 > 50% → 1 小时内补货
  └─ 正常 → 继续监控
        │
        ▼
违规行为检测
  ├─ 收银台无人 > 5 分钟 → 告警
  ├─ 员工抽烟 → 告警 + 截图取证
  └─ 正常 → 继续监控
```

### 2.3 审核维度详细定义

| 审核维度 | 审核内容 | 优先级 | 处理通道 | 准确率要求 |
|----------|----------|--------|----------|-----------|
| 价签合规 | 是否有价签、价签是否与商品对应、价格是否正确 | P0 | 实时 | ≥ 95% |
| 禁售商品 | 是否出现非授权品牌/过期商品 | P0 | 实时 | ≥ 95% |
| 商品摆放 | 特定商品（如红姑娘草莓）是否摆放在指定位置 | P0 | 批量 | ≥ 85% |
| 堆头饱满度 | 堆头是否丰满、是否有明显空缺 | P1 | 批量 | ≥ 80% |
| 陈列标准 | 是否符合总部陈列规范 | P1 | 批量 | ≥ 80% |

## 4. 技术方案

### 4.1 模型选择

| 项目 | 方案 |
|------|------|
| **推荐模型** | qwen3-vl-plus |
| **调用方式** | 实时 + Batch 混合 |
| **输入单价** | 0.0005 元/千 Token（Batch） |
| **输出单价** | 0.005 元/千 Token（Batch） |
| **免费额度** | 各 100 万 Token，有效期 90 天 |

**选择理由**：相比 flash 版本，plus 在复杂场景（堆头丰满度、商品摆放合规性）识别精度提高 25%，符合督导部对准确性的严格要求。

    completed_at    DATETIME,

CREATE TABLE audit_photo (

-- 审核结果表
CREATE TABLE audit_result (

    price_tag_readable  TINYINT COMMENT '价签是否可读',

    placement_neat      TINYINT COMMENT '摆放是否整齐',
    placement_confidence DECIMAL(5, 4) COMMENT '摆放检测置信度',
    -- 堆头饱满度
    stack_grade         VARCHAR(10) COMMENT '堆头等级 A/B/C/D',
    stack_empty_rate    DECIMAL(5, 4) COMMENT '空置率',
    stack_confidence    DECIMAL(5, 4) COMMENT '堆头检测置信度',
    -- 禁售商品
    prohibited_detected TINYINT COMMENT '是否检测到禁售商品',

    prohibited_confidence DECIMAL(5, 4) COMMENT '禁售检测置信度',
    -- 综合结果

    issues              JSON COMMENT '问题列表',
    suggestions         JSON COMMENT '建议列表',
    raw_response        JSON COMMENT '模型原始返回',
    processing_channel  VARCHAR(20) COMMENT 'REALTIME/BATCH',
    created_at          DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (photo_id) REFERENCES audit_photo(id)

CREATE TABLE rectification_order (

    issue_desc      TEXT COMMENT '问题描述',
    issue_photo_url VARCHAR(500) COMMENT '问题照片URL',
    severity        VARCHAR(20) COMMENT 'URGENT/MAJOR/NORMAL',
    status          VARCHAR(20) DEFAULT 'OPEN' COMMENT 'OPEN/RECTIFYING/VERIFIED/CLOSED',
    assigned_to     VARCHAR(50) COMMENT '指派人',
    assigned_at     DATETIME COMMENT '指派时间',
    rectified_photo_url VARCHAR(500) COMMENT '整改照片URL',
    rectified_at    DATETIME COMMENT '整改时间',
    verified_at     DATETIME COMMENT '验证时间',
    closed_at       DATETIME COMMENT '关闭时间',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (store_id) REFERENCES store(id),
    FOREIGN KEY (audit_result_id) REFERENCES audit_result(id)

-- 合规率统计表（按日汇总）
CREATE TABLE compliance_statistics (

### 4.5 钉钉AI表格集成方案

#### 4.5.1 钉钉AI表格应用架构

本产品作为钉钉AI表格应用运行，利用钉钉开放平台提供的以下核心能力：

| 能力模块 | 用途 | 实现方式 |
|----------|------|----------|
| 多维表格 | 数据存储与管理 | 使用钉钉AI表格作为主数据存储 |
| 表单 | 数据采集入口 | 创建门店上传表单，支持图片上传字段 |
| 自动化流程 | 业务逻辑触发 | 配置自动化规则，实现状态流转和通知 |
| AI字段 | 智能识别 | 利用AI字段能力进行图片内容识别 |
| 权限管理 | 数据访问控制 | 配置表格级、行级、列级权限 |
| 消息通知 | 推送提醒 | 通过钉钉机器人推送告警和整改通知 |
| 连接器 | 外部系统集成 | 通过连接器调用外部AI服务 |

#### 4.5.2 钉钉开放平台集成

**钉钉应用配置**：
- 应用类型：企业内部应用
- 运行平台：钉钉AI表格
- 权限范围：
  - `dingtalk:storage:file:upload` - 文件上传
  - `dingtalk:app:table:read` - 表格读取
  - `dingtalk:app:table:write` - 表格写入
  - `dingtalk:user:readonly` - 用户基本信息读取
  - `dingtalk:message:send_as_bot` - 消息发送

#### 4.5.3 前端技术适配

**运行环境要求**：
- 运行平台：钉钉客户端（iOS/Android）内置浏览器
- 技术框架：钉钉AI表格小程序框架（基于钉钉小程序技术栈）
- 兼容性要求：
  - iOS 13.0+
  - Android 8.0+
  - 钉钉客户端版本 6.5.0+

### 4.6 关键技术实现

| 技术点 | 实现方案 |
|--------|----------|
| 前置过滤 | 规则引擎处理简单问题（模糊、非标格式），减少 60% AI 调用 |
| 两级审核 | 关键项实时处理（价签/禁售）；次要项批量处理（堆头/陈列） |

| 图片比对 | 整改前后照片特征向量比对，验证整改效果 |
| 钉钉集成 | 通过钉钉开放平台API实现数据读写和消息推送 |
