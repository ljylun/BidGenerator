## 06. Hash函数与MAC：文件有没有被动过手脚？

前面我们学的所有工具（AES、RSA），都是为了解决一个问题：“怎么不让黑客**偷看**我的信息”。
但黑客有时候很损，他不偷看，他直接搞破坏。

比如你在网上给银行发指令：“转账给张三100块”。
黑客截获了密文，虽然他看不懂，但他随手在密文里篡改了几个字节。等银行解密出来，指令可能变成了“转账给李四10000块”。
这时候，加密已经没用了。我们需要一种防伪机制，来确认文件“连一个标点符号都没被动过”。
这就轮到 **Hash函数（哈希/散列函数）** 登场了。

### 白话化：给文件按指纹

- **脱西装的白话**：
  如果把文件比作一个人，Hash函数就是提取这个人的“指纹”。
  不管这个文件是一句话，还是一部几十 GB 的高清电影，只要丢进 Hash 机器里，它都会吐出一串固定长度的短代码（比如 256 个字符）。
  这串代码就是文件的指纹。
  
- **直觉先行：指纹的三大铁律**
  1. **免碰撞**：世界上不可能有两部不同的电影，提取出来的指纹一模一样。
  2. **雪崩效应**：就算你只把文件里的一个逗号改成了句号，提取出来的指纹也会变得面目全非（像雪崩一样）。
  3. **不可逆**：你可以从文件算出指纹，但绝对不可能通过指纹反推出文件长什么样。

> ☼ **热身例子（怎么用Hash防篡改？）**
> 
> 你在网上下载一款软件，怕中途被黑客植入木马。
> 官方网站上会写着：“这个软件的 SHA-256（一种常用的Hash函数）指纹是：A1B2C3D4...”。
> 你下载完软件后，自己在电脑上对软件算一遍 Hash。
> 如果算出来也是 A1B2C3D4...，说明文件是原装正品，可以放心双击。
> 如果哪怕错了一个字母，说明这文件在半路上被人动过手脚，立刻删掉！

### MAC：带密码的指纹（消息认证码）

Hash 函数看起来很完美，但它有个漏洞。
如果你和朋友通信，你把信件和信件的 Hash 指纹一起寄过去。黑客截获了信，不仅改了信的内容，他还顺手用 Hash 函数帮你**重新算了一个新指纹**，一起发给朋友。
朋友收到后一核对：“嗯，信和新指纹对得上”，就被骗了。

为什么会这样？因为 Hash 函数是公开的，谁都能算。
怎么解决？
我们给 Hash 加上一把“钥匙”，这就变成了 **MAC（Message Authentication Code，消息认证码）**。

- **脱西装的白话**：
  MAC 就是“只有你知道密码，才能按得出的防伪指纹”。
  你和朋友提前约定了一个秘密的“密码K”。
  发信时，你把“密码K”和“信件”混在一起，扔进 Hash 机器里，算出一个指纹。
  黑客截获了信，就算他改了信，但他不知道“密码K”，他绝对算不出匹配的新指纹！朋友一核对就会发现造假。

**这一章要带走的东西：**
- Hash 函数是文件的“指纹提取器”。文件改动一丝一毫，指纹全变。
- 常用的 Hash 算法有 MD5（已淘汰）、SHA-1（已淘汰）、SHA-256（正在用）。
- MAC 就是加了密钥的 Hash。它不仅证明文件没被改过，还证明“这文件确实是知道密码的自己人发出的”。

**就这样。**
